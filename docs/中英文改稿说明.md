# 中英文改稿说明

当前先制作简体中文与英文。文本经编辑、校对后放入游戏语言包，游玩时不请求翻译模型。其他七语待文案稳定后制作。

## 编辑位置

| 内容 | 文件 |
|---|---|
| 中文正文、序尾、档案、题目、回顾 | `engine/workspace/sanluisrey/final_game.json` |
| 当前英文主稿 | `engine/workspace/sanluisrey/i18n/en/final_game.json` |
| 统一译名 | `engine/workspace/sanluisrey/i18n/glossary.json` |
| 上次确认英文时的中文快照 | `engine/workspace/sanluisrey/i18n/en/source-baseline.json` |
| 中文分章制作稿 | `engine/workspace/sanluisrey/authoring/` |

原工程 DEBUG 文案编辑器写中文主稿，运行方式见 `engine/doc/06-copyedit-editor.md`。英文可直接编辑对应 JSON；增量同步会复用未改中文段落的当前英文，包括人工润色。

保留 `id`、答案、`[[NPC1]]`、`{{e_...|显示名}}` 等控制标记。正文、标题与显示名可改；控制 ID 改动会影响存档，须另做迁移。

## 中文改完后，只修受影响的英文

1. 运行 `npm run i18n:status`，只读查看待同步段落。有待审文本时返回非零，便于检查流程发现遗漏。
2. 运行 `npm run i18n:prepare`，生成英文目录中的 `revision-pending.json`（新中文、旧译参考、上下文和路径）与 `revision-translations.json`（待填内容）。已有待审文件时拒绝覆盖。
3. 将确认后的译文写成 `revision-translations.json` 的“路径 → 英文”键值对。每项待审内容都要填写，不能多填其他路径。
4. 运行 `npm run i18n:merge`，检查控制标记与语言包结构，归档修订，再替换英文包和中文基线。
5. 运行 `npm run check:release`，再在浏览器检查修改过的段落与选项。

准备与合并之间，若中文、英文主稿、术语表或中文基线又被改过，合并会停止以保护新增修改。先备份待审清单与已填译文，协调主稿后再生成新清单；不要直接删除尚未保存的人工译文。

人物、地点、物件和概念名称由术语表维护。修改时同步更新 `glossary.json` 的 `zh-CN` 与 `en`，再准备、合并；正文中同一 ID 的显示名会统一替换。只改英文主稿里的名称字段，下次应用术语表会恢复统一译名。

没有文本变化、只有素材路径或编排变化时，允许准备／合并零条译文以同步非文本结构。英文校验仍会执行。

## 避免误覆盖

- 日常 `npm run build` 只构建，不重新生成主稿。
- `compile_slr.py --replace` 会从 `authoring/` 重建中文主稿，与编辑器修改对齐后才运行。
- `tr_*.json` 是首次翻译分片，日常以当前英文主稿为准，不用旧分片覆盖润色后的英文。
- 正文改稿维持稳定 ID，可使中英文共用存档；改变答案、章节结构或删卡须另查旧档。

八项回归覆盖单段中文改动、卡片重排、插入段落、独立润色英文、只换素材，序章／曲名改动，以及译名改动／缺少英文名称的拦截。结构校验不代替文学编辑和原著核对。
