# 情节卡解谜 · 游戏设计指南（README_game）

> 这是一套「离散式叙事」文字解谜游戏的设计规范：把一个完整故事拆成几十张匿名情节卡，玩家像拼拼图一样把故事拼回来。
> 本文档与具体故事无关，讲清**这种游戏适合什么项目、有哪些系统、各系统的量化设计规则、内容如何生产、质量如何检测、以及踩过的坑如何规避**。技术实现见 README_dev.md。

## 1. 一句话玩法与体验参照

一部故事被拆成几十张残缺的情节卡：人名留空、页序打乱。玩法是——**补回名字、排回次序、集齐档案，答出每卷末尾的完形填空**，把故事重建起来。

**这是玩法描述，不是给玩家安排的身份**：游戏内的故事文本（开头、过场、结局）不得把玩家写成「拾遗人」「档案修复员」「整理残卷的人」之类的角色，也不得由某个框架叙述者向玩家交代活计——故事框里只讲故事，操作说明一律留给 UI 层（见 §4.7）。

体验上接近《奥伯拉丁的回归》（按空格推理人名）×《Her Story》（关键词检索式碎片叙事），外加两层结构：**时间轴排布**（把卡片放回正确的时空格子）与**人物档案**（熟悉度换来的背景资料卡）。

## 2. 适合什么样的项目

适合：

- **中短篇、人物关系密集的故事**（3~10 万字原文，改编后卡面 2~3 万字）：人物多、阵营交错、有"谁做了什么事/谁是谁"的推理空间；有明确的**时间线**（能切 3~5 个卷）与**空间变换**（能提供 10+ 个具体地点）。如果是更长的原文，需要先进行故事抽离缩写。
- 有记忆点强的**关键物品**（信物、兵器、地图）和**名场面**（场景戏），方便做词条与悬念。
- 目标时长 60~120 分钟的单机休闲解谜，纯文字 + 立绘头像即可，不需要复杂演出。

不适合：人物少于 4~5 个的故事（空格无候选可猜）；时间线含混、场景单一的故事（时间轴和地点空立不住）；依赖大段心理描写而非事件推进的故事（拆不成"卡"）。

参考规模（本模板实例）：悉达多 53 张卡 / 3 卷 / 42 个词条 / 3 道完形填空。

## 3. 核心循环

```
词条库「搜寻」(体力-1) → 得 1 张新残页（人名全是 NPCn，时空模糊）
→ 读残页，点正文里的词条收入词条库（该词条熟悉度+1）
→ 按上下文推理，为每个空选出正确的「人名/地名」→「验证此卡」逐空判定
→ 全对：残页「补完」（体力+1、揭示该卡标题）
→ 把残页放进时间轴：行/列凑齐或连片 ≥4 则「锁定归位」
→ 词条熟悉度攒满 →「分析」解开档案页 → 补全档案留白
→ 本卷「归位+档案」进度 ≥70% → 关卡出口答「完形填空」→ 下一卷
```

**全程不打字**：所有填写都是「点空格 → 弹候选 → 点选」。这是硬规则——自由输入会带来错字、别称、同义词争议，候选池则天然成为"嫌疑人名单"。

## 4. 系统与量化设计规则

### 4.1 情节卡（最小叙事单位）

- **三种形式**：情节（多人场景，第三人称）/ 对话故事（≤3 人）/ 独白（第一人称）。呈现为聊天软件式消息流：旁白居中灰字，气泡一律居左（头像在左、气泡在右），独白用金底斜体气泡。"情节"用于复杂的情节故事，"对话故事"用于对话驱动的情节（对话占比应超过该段字数的70%），"独白"用于呈现人物（其中也可以包含从该人物视角看到的情节发展）。
- **独白可以覆盖人物行为（改编手法）**：原著里常有大段描写某个人物「做了什么」的段落——赶路、布置、动手、等待——这类内容没有对手戏，做成"情节"会变成流水账，做成"对话"又无人可谈。**把它改编成独白**：约 **30% 行为描述 + 70% 该人物的自言自语 / 对自己行为与状态的陈述**，仍然计为【独白】形式。要点：行为部分只留必要的动作骨架（在哪、正在做什么），情绪、动机、盘算、身体感受都交给第一人称说出来；不得退化成"我做了 A，然后我做了 B"的纯行为流水账，也不得违反 §4.1 的「暧昧人物不写自白式独白」——覆盖行为不等于允许作者判词。
- **对话必须气泡化**：人物表中角色的台词一律用气泡段呈现（已具名角色用 speakerEntry 气泡、待猜角色用 NPCn 槽位气泡），不得把"某某道：「…」"写在旁白段里；动作神态可用括号写进气泡开头，如 林冲：「（酒醒，大喊）甚么人敢吊我在这里！」。**纯配角（不在人物表的角色，如酒保、庄客、管营）的对话也用气泡**，用 `speaker:"酒保"` 文本名标记：不为其绘制头像，引擎以配角名字的第一个汉字（或第一个字母）生成**淡色"首字印章"**作头像，颜色必须淡、不抢视线。例外可留旁白：①群体台词（众人道）；②诗歌唱词；③回顾/片段式引语（"那句「智取」"、对骂片段）；④叙事上刻意隐藏身份的人物（如未点名的"军官"，身份揭示后再用气泡）；⑤困难卡中**登场**但未设空的人物（全匿名纪律优先，不能具名也不能 speakerEntry；只是被提及、并未登场的人不受此限）。
- **语言**：一律现代通俗白话，类似网络文章或通俗小说。改编文言或外语原著时必须重写为现代普通话——对话应呈现人物特点（具有一定的人物识别度），但不得文白夹杂或整段搬原文。原著名句可化用，句式要顺现代语法。
- **字数量化（硬性设计参数）**：全卡平均 **X 字**（策划时在 meta.cardSpec 设定，默认 **700**，去标记计）。每卡写作前先定字数档 `len`：
  - **S 短篇 = 60–70%X**（约 420–490）：独白卡、低难度卡；
  - **M 标准 = 85–115%X**（约 600–800）：常规情节卡/对话卡；
  - **L 长篇 ≈ 130%X**（约 880–950）：群戏、关键情节、多人对话。
  - 全卡平均须落在 [92%,108%]X。每卡事件量 1–2 个：清晰（看得懂发生了什么）、完整（能推出时间与上下文衔接），不把一大段情节塞进一张卡。
- **规模**：每卷 12~25 张，全作 40~80 张。卡面正文每段 1~4 句；每卡空格 2~5 个（人名空为主，地点空 0~1 个）。
- **匿名机制**：要猜的人物一律显示 `NPC1/NPC2…`（灰章 + 剪影头像），编号**每卡独立**（卡 A 的 NPC1 与卡 B 无关，否则答案跨卡传染）。地点写得模糊但不撒谎。
- **可推理性（硬性设计规则）**：每个空位都必须能唯一推理。同卡多个人物空时，**每人必须有差异化识别点**（外貌/绰号/言行/与他人关系），严禁"NPC1 和 NPC2 一起站在台上"式并列无区分——玩家即使猜出是哪两个人，也无法对号入座。团伙作案时，逐人给特征（如：爬墙点火的是伴当、太尉遣来的是虞候、庙里复仇的是教头）。若凶手在团伙中，本卡或其他卡必须提供足以分辨的信息。
- **填写与验证**：草稿随时改、无消耗；点「验证此卡」统一逐空判定——对的锁定金光、错的清空抖动并记一次「错」。全对 → 补完：**揭示该卡标题**（卡头与时间轴同步显示）、体力+1、答案词条熟悉度+1。
- **渐进呈现**：首次打开逐条上屏（~250ms/条），已读卡直接全显；**不自动滚动**（用户不碰，滚动条停在顶部）。
- **难度三档（实测比例）**：
  - `简单 ≈30%`：**不填地点**，只填人名。适合独白卡（内心戏，地点不言自明）。
  - `普通 ≈55%`：人名 + 地点，基准难度。
  - `困难 ≤20%`：**登场人物全部匿名**——本卡场景里的人一律 NPCn 待填（3~4 个人物空），无已知发言人（不用 speakerEntry）。留给多人名场面与高潮戏。剧情关键的"伪装名/代号"（非真实人名）可以裸文本保留，但要在文档中登记。
    **注意困难不等于"正文一个人名都不许有"**：受限的只是**本卡待猜**的那几个人，而这一条本来就由匿名铁律统管（任何难度都适用），与困难与否无关。被顺带提及、并不在本卡待猜之列的第三方（「那是{{某某}}的公司」「{{某某}}两年前留下的规矩」）照常可以做 chip——否则困难卡连交代背景都做不到，词条也失去了收集来源。
- **首卡规则（玩家读到的第一张卡，硬性设计规则）**：第 1 关开局解锁 **2 张**卡（`startUnlocked`），其余关卡照旧从搜寻起步。①其中一张必须是**过场钩子的正文版**——过场末段停留的那个场面（太顺利的演示、靠岸的小船、门口不肯走的人），玩家读的第一张情节卡就应当是它或直接接着它；②任何一张开局卡的**第一段都不得是世界观 / 制度 / 历史科普**，必要背景挪到第二段以后或织进后文旁白；③两张卡合起来至少覆盖三个教学点：一个用开局赠送词条就能填的空（教「填」）、一个必须去搜寻才能填的空（教「搜」）、若干可点的词条 chip（教「收」），且「搜」的链条要在 3 张卡内闭合（赠送词条 → 搜到的卡里有那个名字 → 回填）。④开局赠送词条（`levelStartEntries`）只给**本卷之问里已经点到的人**，没被问到的留给搜寻。
- **提示**：情节卡**不再写提示文案**（`hints` 字段已废弃并从全部作品数据里删除）。玩家的「⚡提示」是机制而非文案：花 1 体力，替玩家填对已收集到答案的空位；答案还没收集到的空位只临时亮出 3 秒（震动）再还原，等于告诉玩家"去词条库把这个名字找回来"。用量不计入评星。
- **一事一卡（禁止事件复用，硬性设计规则）**：同一事件（同一时间 + 同一地点 + 同一冲突核心）只能占**一张卡**。角色列卡与情节列卡涉及同一事件时，角色列卡必须提供**新事实 / 新视角 / 新后果**之一；**同一句金句、同一个结局细节不得在两张卡里各讲一遍**。卡位是全作最稀缺的资源（40~80 张要装下整本书），重复一次等于原著少覆盖一章；玩家读到第二遍还会误以为自己重复解锁了同一张卡（校验器机械检查重合片段）。
- **暧昧人物不写"自白式独白"（人物塑造规则）**：对原著刻意留白其动机的人物（多为纪实作品的被告/加害者），独白卡只写**其本人相信的自我合理化逻辑**（"我承诺过就必须做到"），**不得写"我知道我在骗人""故事只要动人就是真的"这类作者判词**。判断权交给玩家：把一个连作者都不敢下定论的复杂人物写成自知的阴谋家，等于把原著最有价值的争议空间删掉，反派也随之扁平化。加害者的可怕之处往往正是"她可能真的相信"。
- **弧光过渡（人物立场反转必须有铺垫）**：人物立场发生反转（敌→友、旁观→行动、追随→揭发）时，反转前后的关卡之间必须至少有**一张过渡卡或一处过渡提及**；**不得跨卷断线后突然反转**（玩家上一卷把他记成反派，下一卷他忽然成了揭发主力，会直接认知失调）。反转动机必须延续原著（是"旧账未了"还是"良心发现"，不许顺手洗白），校验器对"第 N 关有来源、第 N+1 关断线、第 N+2 关又出现"的人物给出警告。

### 4.2 词条库（四类词条）

- 四类：人物 / 地点 / 物品 / 概念。词条是**一切系统的通用货币**：点击收集、搜寻发动机、熟悉度燃料、档案主体、完形填空候选。
- **收集**：点正文里的词条 chip 收入词条库（同卡同词条熟悉度只计一次 +1）。人名/关键物靠正文 chip 获得；**地名也必须靠正文 chip 逐渐获得，不做开局赠送**——获得与猜对分离，阅读驱动一切。**打勾（✓）与熟悉度自增解耦**：即使熟悉度已满，本卡内首次点击仍记录"已点过"并显示 ✓——绝不能让点击看起来无效（玩家会困惑）。熟悉度自增才受上限封顶。
- **同卡人名 chip 唯一**：同一张卡里，同一个人物的可收集 chip 至多出现一次，配置在该人物本卡**首次登场**的位置；后文再提到一律用裸文本。同卡重复出现同名人名 chip 会稀释阅读节奏、徒增无效点击（校验器机械检查）。
- **有对话必可收集**：人物表中的角色在某卡登场、且有气泡对话、且不是本卡待填的匿名 NPC 时，必须在本卡正文中以 chip 形式出现（通常放在首次登场的旁白里，speakerEntry 气泡的发言栏不算收集入口）——否则玩家从头到尾收不到这个名字，会好奇此人是谁（校验器机械检查）。
- **展示**：四类词条均为双列卡（人物带圆头像，其余无图），组内按本关熟悉度上限降序。
- **熟悉度（分关刷新）**：跨卷时词条收集状态与档案进度**继承**，但熟悉度**清零重攒**——否则主角在第一卷就满级，后两卷熟悉度系统形同虚设。
- **熟悉度上限**：= 该词条在本卷的出场数（正文 tag 卡数 + 作为唯一答案的卡数），**不做容错折扣**——上限就是本关来源数（曾试过"来源 ≥3 时按 80% 折扣"的容错，实测体验不佳，已取消）。数组答案（多地点任一即对）的卡不计入上限：补完时只给玩家实际选中的那个词条 +1，若计入会让未被选中的词条永远攒不满。
- **词条创建必使用（设计规则）**：凡在故事中创建的人物/地点/物品/概念，在其被创建（首次登场）的关卡内至少要被"使用"一次。使用的两条路径（至少满足其一）：
  - **a. 档案分析**：该词条在本关有可解锁的档案页——这种情况下允许其本关熟悉度上限 == 1（只出场一次也有存在意义：读满即可分析）；
  - **b. 叙事使用**：在本关其他卡的正文中被提及（tag），或作为需要填写的 NPC/地点答案——不走 a. 路径的词条必须走 b.，这意味着它在该关的熟悉度上限必然 ≥ 2（创建处 1 次 + 使用处至少 1 次）。
  两条都不满足的是"死词条"：收了没用、攒不出档案也填不进任何空，只会稀释词条库，设计时应删除或并入其他词条。
- **角色重要度分层（设计规则）**：即使项目是群像戏，也必须塑造出明显的主角/配角区分——主角在一关内可达到的熟悉度上限应**明显超过**配角们（体现为正文 tag 与答案来源数的差距）。词条库与档案列表都按本关熟悉度上限降序排列，主角来源足够多才会稳定浮在列表顶部，成为玩家的注意力锚点；若人人上限相近，排序失去意义，玩家也抓不住故事重心。
- **重要度三层 `tier`（写进数据的硬性规格）**：每个词条标 `tier: "core" | "major" | "minor"`（缺省视为 `major`），**不同层的文字量与档案规格不同**——同样简单的词条堆一屋子，玩家分不清谁是重心，读档案也毫无层次感：
  - `core` **重要**（全作 3~6 个：主角、对手、叙事者）：`desc` 30~60 字；**跨卷 ≥2 页**档案；每页 5~6 字段；每页 ≥2 处留白；每页至少 1 个 ≥25 字的**细节/金句型**长字段。
  - `major` **一般**（全作 12~20 个：关键配角、关键物品与概念）：`desc` 20~40 字；1~2 页档案；每页 4~5 字段；每页 ≥1 处留白；字段正文平均 ≥14 字。
  - `minor` **低重要度**（其余）：`desc` 12~30 字；可以没有档案页（仍受"创建必使用"约束）；若有则 1 页 3~4 字段。
  - **禁止干瘪字段**：任何档案字段正文不得少于 8 字。"职位：首席财务官"这种是标签不是档案，要写成"2006 年入职的首席财务官，每一份给投资人的材料都要过他手"。
- **受害者与普通人必须进入词条系统（纪实改编硬性规则）**：凡因主线事件**直接受害的普通人**（患者、受灾者、被裁员工、家属），**至少 2 名必须做成人物词条并配档案页，其中至少 1 名要进入某一关时间轴的角色列**。原因：词条/熟悉度/档案是玩家感知"谁重要"的**唯一机制**——若只把高管、董事、投资人、监管官员做成可收集可分析的词条，把受害者写成一次性配角气泡，作品会自动滑向"上流社会宫斗记"，原著对代价与苦难的批判力度会在系统层面被抹平。批判性题材尤须自查：**谁被做成了词条，就等于宣告了谁值得被记住**。
- **配角气泡（`speaker`）只用于一次性功能角色**（酒保、护士、接警员）；凡在**两张以上**卡中出现、或承载主题重量（受害者、见证者、关键旁观者）的角色，一律升格为人物词条，配头像与档案。
- **「分析」**：熟悉度满 → 读条（~2 秒）→ 解开该词条本卷的档案页。分析入口放档案界面，不放词条库（动线：读满 → 去档案）。
- **「搜寻」**：耗 1 体力，解锁本卷含该词条的 1 张新残页（唯一获卡途径）。**按优先级发放（回答>收集，严格分层）**：① 用词条库现货就能**完美作答**的卡最优（+10000，空位越少越优先）；② 用「已获得残页里还能收集到的词条＋现货」可完美作答的卡次之（+1000，空位越少越优先）；③ 再次是能收获**新有效词条**（人物/地点、或还能搜出更多残页的词条）的卡（+100，按新词条的本卷熟悉度上限取最大加分）；④ 其余按部分可作答空位、可预期空位与剩余收集价值兜底（恒 <100）。同分按卡序。完全随机会让玩家连翻无关卡；先到先得会让顺序呆板。**独白防连发（硬规定）**：刚拿到某角色的独白后，下一次搜寻中该角色的其余独白优先级直接置 0——同一角色的独白**永不连发**，必被情节/对话（或另一角色的独白）隔开，独白回归"喘息拍"的定位；若当下确实没有别的可发之卡则照常发放（永不卡死）。**连发抑制**：独白之外，与刚拿到的卡同角色同形态的候选，第 1 张重复只在同层内让位，连着 2 张后直接跨层降权——同类连发至多 2 张。**红点导航**：词条库有搜寻按钮时，优先级最高的那颗「搜寻」前带闪烁红点——一直点红点就是最佳路径。

### 4.3 档案卡

- 词条的"展开版"：立绘/头像、姓名、不剧透的小传、家族关系、特长。部分字段**留白**，用类型匹配的已收集词条逐空核对填满，全对盖「完」印。
- 核心人物做**多页档案**（如少年/学徒/归人），分卷解锁——这是剧情复看的钩子。数量参考：全作约 20 个有档案的词条、30 页上下、40 处留白。**页内字段数与字数按 `tier` 分层**（见 §4.2）。
- **留白答案分布（硬性规则，防"所有问题都在问主角"）**：
  - 单个词条被引用为档案留白答案的次数 ≤ 全作留白总数的 **12%**，且绝对次数 **≤5**；
  - **同一页内的多个留白不得指向同一个词条**；同一词条不同页的留白 `label` 不得重复（别出现两页都问"祖父"）；
  - 全作留白答案的**去重词条数 ≥ 留白总数的 60%**；
  - 留白问题要覆盖四类词条（人物/地点/物品/概念），**不得全是"谁是谁的谁"**——问地点（造假演示发生在哪）、问物品（他攒出的机器是什么）、问概念（他的管理风格叫什么）都比再问一次主角名字更有信息量。
  - 反例（实测踩坑）：坏血初版 44 处留白里有 9 处答案都是主角，几乎每翻开一页档案都在重复填同一个名字，档案系统退化成点名游戏。
- **列表排序**：可分析（熟悉度已满、有未解锁页）的词条置顶，其余按本关熟悉度上限降序——可操作的永远浮在最上面。
- **列表图标与状态徽标**：有档案图的词条用图片作图标（不用"首字印章"）；徽标三态——金色「可分析」（熟悉度满、有未解锁页）、「已分析」（页已解开但留白未补完）、绿色「正确」（已解开页的留白全部核对通过）——状态一眼可辨。左侧词条列表与情节卡列表同宽（300px），给状态留足空间。
- **多关档案页竖向排列**：详情区按关卡顺序依次展示各页（小节头「第N关 · 标题」+ 页内容），未解锁页显示「第N关 · ？？？ 🔒」——一屏纵览全部进度，不用页签来回切。
- **提醒动线**：存在「可分析」词条时，主界面「档案」页签亮红色小圆点；「补全档案空缺」候选弹窗中每个词条显示简介与圆点熟悉度（与词条库同款），选择时不用回词条库查。

### 4.4 时间轴

- **结构**：行 = 故事时间段（每卷 5~8 段），列 = 情节列 + 主角 + 重要 NPC（列头带角色头像；**未获得的人物列只显示剪影与「？？？」**，不提前泄底；**情节列头带作品主题图标**，尺寸与人物头像一致，见 §4.8）。情节列每行一卡；NPC 列只在该人物有独白/对话的时段有卡。
- **行头时间点名默认隐藏（防剧透）**：时间段的名字本身就是剧情走向的地图，默认只显示「时间 1、时间 2…」；行头下方有一个不起眼的「提示♥」小按钮，点击**花 1 体力**提前揭示该时间点的名字；**整行全部补完且放对（锁定归位）时自动揭示**。已揭示状态入存档、分关记录。
- **格子即画框**：时间轴表格铺满中列宽度、格子大幅增大；卡片**补完后**放入格子，即以该卡 16:9 CG 铺满整格作底色，标题压深色渐变白字——归位的过程同时是「把故事画卷拼回来」的过程（未补完的残页不显示 CG，防剧透规则与情节卡页一致）。
- **角色列卡的列主必须是 NPC1（设计规则）**：凡隶属于某个角色列的情节卡（对话/独白卡），该列人物必须就是本卡待填的 **NPC1**——列主即本卡第一个要猜的人。这样"猜出 NPC1 是谁"与"这张卡归到谁的列"是同一个推理，归位时列头头像即答案锚点；若列主写成 NPC2/NPC3 或根本不设空，填写与归位就脱节了。
- **内容量强制规则（校验器红线）**：①每行至少 2 张卡；②情节列每行恰好 1 张（情节列必须填满）；③每个角色列至少 2 张卡；④所有角色列的有效格子加在一起，必须**超过角色列格子总数的 40%**。设计网格时先用这四条算好行数与人物卡数：人物卡需求 ≈ 行数 × 角色列数 × 42%，行数越多需要补的人物卡越多，别贪行。
- **三列布局**：时间轴页为 左｜中｜右 三列——左列「待归位情节卡」（竖排，已补完的排前面，不与已放入的混杂；未补完的卡用与情节卡列表同款的**模糊标题** + 正文摘录，不写「残页」字样）、中列时间轴表格、右列关卡出口面板（**与情节卡页的词条库同宽**；不再有「关卡出口」字样行；头部第一行是**卷名**，与「故事」页同源、同字——取本卷过场首段的「第N卷 · 名字」，如「第一卷 · 弃家求道」，闸门数据里**不再有独立的关名字段**；其下是本卷之问；「展开问题 / 收起问题」大按钮内嵌进度条，70%/100% 处各有一个里程碑圆点，100% 时按钮上标注「可自动填写」；按钮下方灰色居中一行「时间轴 x/y　档案 x/y」计数，每项底部贴一条迷你进度条；完形填空题面内嵌展开，不是弹层）。未补完的卡放进格子后，格内也是**模糊标题 + 预览正文**铺满，不留空白。
- **归位锁定（两种触发，单格放对不锁定）**：
  1. **整行/整列**：某行（或某列）的**全部设计卡**都已补完且放对 → 该行/列扫光并全部锁定（未补完视为未凑齐；**行/列内若混入了放置错误的卡，即使设计卡全部放对，也不得判定该行/列完全正确**）；
  2. **连片**：沿"相对位置正确"（相邻两格的正确格坐标差 == 当前格差）连成的簇，未锁定成员 **≥4** 且全部补完、全部在正确格 → 一次性全部锁定。
- **残页（未补完）不参与连片延伸与绿线提示**；行/列锁定则要求该行/列全部设计卡都补完并放对。
- **绿线提示**：相邻两格相对位置正确（哪怕都不在正确行/列）时，两格间画绿色连接线，给摆放线索；双方均锁定后消失。
- **放错零成本**：不扣体力、不给负面反馈，自由移动/交换（交换时被挤出的卡回待归位区）。惩罚放错只会把玩家逼去抄攻略。
- **关卡带（右栏「关卡出口」上方）**：横排列出关卡，每格只有「第 N 关」+ 小字「N 段情节」。**不显示关名与星级**——关名会剧透走向，段数不会，却正好回答了「这部作品还有多长」。已通关的关可点击进入**只读回顾**（见下条）；当前关高亮；未开启的关虚线灰显、不可点。**恒为一行、一页 3 关**：右栏窄，关卡多了不换行也不出滚动条，改成两端翻页，当前关换页时自动翻到它那一页；每格尺寸固定，末页不满 3 关时是居中留白而不是把格子拉长。关卡集合一律从数据推导（`timelines` 的键），绝不写死。
- **只读回顾模式**：点关卡带里已通关的关，时间轴整块换成那一关来渲染。卡片的补完与归位状态本来就是跨关保留的，所以不需要任何快照。回顾态下：格子不可放置、不可交换；时间点名**全部揭示**（都过去了，无所谓剧透）；左列「待归位情节卡」隐去；右列的闸门面板收起、**但右栏本身留着**——关卡带就在它顶上，下面还有一个恒定在场的「回到第 N 关」按钮（关卡带会分页，当前关未必在这一页上，不能只靠它回去）；点格中残页在**原地弹只读浮层**重读（不切页签——情节卡列表只列当前关，切过去会左右不一致）。回顾**绝不动 GameState**：不清熟悉度、不覆盖进度，与 `debugJumpLevel` 是两回事。
- **卡底跳转（已归位的卡）**：情节卡正文底部**居中一行 CG 缩略图**——**上一节**（同列、时间 −1）、**下一节**（同列、时间 +1），以及**同一时段**的其他卡（同行）。每格用目标卡的 16:9 CG 作底图，压深色渐变、白字压标题，左上角小角标写关系——时间方向写「上一节 / 下一节」并在图的左/右边缘融进一枚方向箭头，同时段项写该卡所属的列并在名字前带一枚小头像。**时间方向与同时段之间用一条分割线隔开**：顺着一条线往下读，和看同一时刻别人在做什么，是两种不同的去处。整条刻意长得跟旁白与气泡完全不同：它不是故事的一部分，是"接着往下读"的入口，一眼就该认出来。目标卡未补完时**不露 CG**（与格子同一套防剧透规则），退化成纸色斜纹虚框 +「？？？」且不可点。这让拼完的故事可以顺着"时间线"或"横切面"两个方向连读。

### 4.5 关卡（分卷）与完形填空

- 故事按时间切 3 卷左右，卷间一道**完形填空**（5~6 空）。答案两类：人物/物品（该词条**本卷档案页必须已全部补完**才进候选）与情节标题（该卡必须已归位揭示）。答错可重答，只计「错」数。
- **候选弹窗排序**：词条按 分类 → 本关熟悉度上限 → 全作熟悉度上限 排列；「剧情」组按时间轴行列排成与主界面同构的表格（每格一张图 + 名字），位置即故事坐标，翻找有据可依。
- **本卷之问（`gates[].question`，硬性规则）**：每卷用**一句问句**说清这一卷要搞清楚的事（「两个一起长大的朋友，为什么走上了两条路？」）。它是本卷所有谜题的总纲：过场结束后单独一屏亮给玩家、关卡出口面板头部常驻、新手引导的目标弹窗与顶栏常驻提示首条也用它。要求：以「？」结尾、≤30 字、只问故事里的事（不用「你」、不含玩法词汇）、答案必须在本卷内可得（过关那一刻能被回答）。三卷的问句连着读应当是一条递进的线。
- **卷末题即「谜题清单」，开局就能看**：完形填空的题面不再藏到 70% 才能看——进关起点「展开问题」就能读题；进度不足时**只有题面**，没有答案栏、不能填、不能提交，也不给任何提示，到 70% 后答案栏才出现。因此每道题要标**可见时机** `revealAt: "start" | "gate"`（缺省 `gate`）：
  - 每卷 **≥3 道 `start`**（开局可见），否则清单立不住；
  - `start` 题面**不得泄底**：不得含本卷任何待猜人物 / 地点的真名，不得点破某人的结局或立场反转（「披上黄衣、皈依僧团的是」= 提前告诉玩家有人皈依了）；泄底的题要么改写成不泄底的版本，要么标 `gate`（开局显示为「？？？」，70% 后揭开）；
  - 题面写法从「复述情节再挖空」改为「先把悬念问出来」：「教他读书写字、带他做生意的那位富商是谁？」读起来像一个还没解开的问题，答完像揭晓；
  - 全作之问（`meta.tagline`）、本卷之问、题面、回顾末页、结局回应——五处要能互相对上号，写作时在设计稿里列一张「问题-答案对照表」。
- **闸门进度条** = （残页归位数 × 25 + 档案补完页数 × 10）/（本关卡数 × 25 + 本卷档案页数 × 10）——归位权重为档案的 2.5 倍（**算法只用于设计与校验，界面上只显示百分比，不展示算式**）：
  - **≥70% 开闸**（不要 100%——最后一两张卡的追逐很挫败）；题面从进关起就能「展开问题」读到（`revealAt:"gate"` 的题显示「？？？」），70% 前只有题面——不出答案栏、不能填、不能提交、不给任何「可以答了」的提示；到 70% 后答案栏才出现，逐题作答（问题在上、答案在下一行，字号与正文一致）；
  - **100% 解锁「自动填写」**：一键把答案填入候选态，**不自动提交**——玩家仍须自己点「核对答案」。这是纯福利，**不影响评级与得分**。
- **难度**：两档，随时可切（页签栏「星级」面板里切，面板同时列出两者差异与本关扣星明细）。**简单（阅读者难度，默认）** 满星 ★★★；**困难（解谜玩家难度）** 满星 ★★★★★。困难 → 简单任何时候直接切；简单 → 困难时若本关完成度（= 闸门进度）**≥20%**，先弹确认「这一关已经完了很多，切换到困难模式无法获得满星评价」，确认后本关满星只按 4 计（`perLevel.hardLate`）。两者只差四处引导：① 情节卡列表「可填写」标注只在简单给（困难一律「待补全」）；② 「⚡提示」对未收集的地名，简单亮出答案、困难只震动；③ 词条库「最佳搜寻」红圈只在简单给；④ 时间轴单格放对的勾标 / 金环 / 成功音只在简单给（困难要等行 / 列 / 连片锁定才知道）。其余完全一致。
- **评星**：`分数 = MaxScore − Deduction`，最低 0，再化成 ★。MaxScore：简单 3、困难 5、迟切困难 4。Deduction：本关**每 3 次错误 +1、每 3 次休整 +1**——两个计数都按关记，**过关即换新关计数**。提示、自动填写不参与。页签栏面板两行：上行难度名、下行星数（困难五星间距更紧）。
- **得分**：`关得分 = round(100×进度) + 星级加成（每星 100：5/4/3/2/1/0 星 → 500/400/300/200/100/0）`，结局结算总分与各关小分（各关满星数随过关时记录 `gates[after].maxStars`）。让"自己答"和"自动答"、早开闸和晚开闸在分数上有差别。

### 4.6 体力

- 定位：**软门槛**，控制解锁节奏，绝不卡死。参考值：初始 8，每进新卷 +4；搜寻 -1；补完一卡 +1；见底时体力数字左侧出现「休整」（+2，不限次；按关累计，每 3 次扣一星，过关清零）。
- 设计目标：全程盈余为正（本实例模拟盈余 15~16 点）。调任何数值后必须用自动通关模拟证明"0 休整可通关"。

### 4.7 辅助系统（缺了就不是完整产品）

- **过场/结局故事**：AVG 大图 + 半透明故事框，**只讲故事本身**。开局流程为 标题页 →「新的开始」→ 第一卷过场（末屏单独亮出本卷之问）→ 主界面**情节卡页**（无片头；首次进关只弹一个「目标」弹窗：本卷之问 + 三行收获，随后引导情节卡与时间轴两个页签）。
  - **故事文本不对玩家说话（硬性规则）**：`frame.levelIntro` 与 `frame.ending` 只叙述故事世界里发生的事，**不得**做下面任何一件：
    - 给玩家安排身份（拾遗人 / 档案修复员 / 整理残卷的人 / 修复员……），或让一个框架叙述者（老编辑 / 守屋老人 / 老馆员……）向玩家交代活计；
    - 旁白使用**第二人称**（你 / 您 / 玩家）——旁白是故事的叙述者，不是对玩家说话的人；
    - 出现**玩法词汇**（残页、页序、人名被虫蛀、拼回去、补回名字、归位、词条、时间轴、完形填空、关卡、存档……）；
    - `meta.subtitle` 与 `ending.credit` 也不得挂身份（不写「拾遗人版」「档案修复员版」）。
    - 过场里若要出现发言，只能是**故事内人物之间**的对话（`speaker` 为故事角色，在场景里对彼此说话），不得越过第四面墙。
    - 需要教玩家怎么玩的话，全部放 UI 层：顶栏「玩法说明」弹层与常驻提示（那里本就是功能文案，不属于故事）。
    - 理由：一旦故事框里出现"名字乱了，你把它拼回来"，作品就从"读一个故事"退化成"听人派活"——原著的语气、纪实题材的重量、文学改编的沉浸感会被一句派活台词冲掉；而且这类框架台词每换一部作品都得重写一遍，纯属重复劳动。
  - **过场的呈现方式决定了它的写法**：过场是一屏一段、逐字上墨、整幅底图不遮挡（`assets.levelIntroImages[N]`）；首段若是「第N卷 · 名字」（≤16 字）就做成题名幕，末尾由引擎追加一屏「问句幕」亮出本卷之问。所以一段就是一页，段数就是玩家进游戏前要点的次数。
  - **过场规格（硬性规则，每卷一致）**：**恒为 5 段 = 1 段卷名 + 4 段正文**；正文每段 60~130 字（目标 100 字左右）。加上问句幕一共 6 屏，这是玩家进游戏前的上限。宁可一页写满 100 字，不要拆成 9 页每页一句——页数一多，玩家点到第四下还没见到一个活人做一件事。
  - **正文用本卷主角的第一人称写**：「我」= 本卷之问所问的那个人（通常也是角色列的首列）。原著本身是第一人称的，沿用原著的叙述者。纪实题材里若本卷主角是作者刻意留白其动机的加害者，「我」改为本卷内**最贴近事件的见证者**（受害者、吹哨人、记者、家属、最早的同事），**不得替加害者自白**（承 §4.1「暧昧人物不自白」）。一卷之内**视点不换手**：一个「我」从头讲到尾，不得旁白→史学口吻→人物→旁白地跳。第一人称不违反「不对玩家说话」——「我」是故事里的人，第二人称仍然禁用；因此「我」引用别人对「我」说的话要改**间接引语**（「他问我为什么还不走」）或去掉人称（「来了？」「来了。」），否则会被校验器拦下。
  - **开场必须有钩子，且钩子前置**：`levelIntro[1]` 的第 1 段正文就要**有人、有事**——一个已经出事的场面（一场太顺利的演示、一条不该出现的小船、一个不肯从门口走开的人），再回到起点；**不得以气氛、风景、抽象概念开场**（听水声、看树影、一个带引号的哲学名词都不算钩子）。**不得把结局的意象搬到开头当钩子**：结局意象的力量全靠前面整本书垫出来，没读过原著的玩家看到的只是一个人在发呆。若原著本身是倒叙结构（先抛丑闻、再倒叙成长），过场必须把这个钩子复现出来——时间轴机制只能正叙（行 = 递增的时间段），不在过场补钩子，第一卷开局就会退化成平铺直叙的传记。钩子要用故事画面来给，不是用"这一箱里全是碎纸"这种元叙述。
  - **第一卷要立两个问题，其他卷只立一个**：第一卷过场必须同时抛出**全作之问**（`meta.tagline` 的故事版，贯穿全作品的谜）和**本卷之问**（`gates[after=1].question` 的故事版）。全作之问放在前两段（由故事里的人问「我」，或「我」自问），本卷之问放在末段收尾；两问要**套叠**（本卷之问是全作之问的第一步），不能各指一个方向让玩家不知道追哪个。第 2 卷起的过场只需在末段落成本卷之问，不再重复全作之问。
  - **先出场，再提问**：问句里点到的每一个人（「两个朋友」「四个人」「三兄弟」）都必须在过场里**登场并有一个可辨认的动作**；开局赠送词条（`levelStartEntries`）里的人也都要露过面。不得让玩家去追一个从未见过的人——过场里从头到尾只有一个人，问句幕却问「两个人为什么分开」，是最硬的结构错误。
  - **过场末段必须落成问句（硬性规则）**：每卷过场的最后一段要把钩子收成一个明确的问题，而且这个问题就是本卷之问（§4.5）的故事版——可以由故事内的人物问出，也可以由「我」自问。画面收在句号上（「天亮时他走了。」）不合格：画面完整，但玩家手里没有被交给任何要解开的东西。校验器机械检查末段含「？」。
  - **末段停在首卡的门口**：过场末段停留的场面，应当就是本卷第一张情节卡的场面或它的前一刻（第 1 卷即开局解锁的钩子卡，承 §4.1 首卡规则；其他卷即本卷第一行的情节卡）。过场收在多年以后、玩家进关第一张读到的却是事发当夜，情绪线就在过场和首卡之间断了一次。
  - **留白**：过场只讲发生了什么，**不解释动机、不替人物下判词**；每卷过场至少留一处「我没有问 / 他没有答 / 我不知道」式的空白，答案留给本卷的卡去补。过场把戏演完了（起因、经过、结果一句带过），卡就没有东西可揭了。
  - **图文对位**：过场只有一张底图，第 1 段正文的时空必须与底图一致（底图画的是少年在岸边，文字就不能是老人在船上）；倒叙框架若非要开在别处，换底图。
  - **全作之问 `meta.tagline`**（可选但推荐）：封面副标题下再压一行，就是把整部作品的悬念用一句问句说出来（「全镇都知道有人要杀他，为什么没有一个人拦住？」）。规则同本卷之问：问句、≤30 字、不用「你」、不含玩法词汇、不挂身份词、不泄露过场之外的情节。
  - **问句、题面与过场的文风纪律**：本卷之问、全作之问、过场正文、卷末题面，一律用**最简单直白的话**——读一遍就知道在问什么、在讲什么。不写谜语、不堆修辞、不用排比与对仗撑场面（把千百种声音、气味、人名排成一串）、不留 AI 味的空泛抒情（「命运的齿轮」「时间的褶皱」「像大地在低语」）；**不用意象代替信息**（一句只有画面、删掉后信息量不减的句子，删掉）；**不概念先行**（在玩家对一个哲学名词毫无概念时，拿带引号的名词做悬念）；**不口吻打架**（纪录片式的年代交代和散文诗腔不得同框）；**不留歧义句**（读者要停下来猜"这句到底指什么"的句子，重写）。写之前先翻 `workspace/{作品}/book/` 里的原著几页，照原著和译本的语气来；宁可像一句家常话，不要像一句广告词。
  - **结局 ≥8 段，且必须齐备四件事**：①**事实结算**（发生了什么、怎么收场）；②**代价结算**（谁受了伤害、多少普通人被波及、说真话的人付了什么代价）；③**主题落点**（这部作品的道德判断，与全作核心概念呼应）；④**余响**（故事之后的世界：留下了什么、谁还在、日子怎样继续）。**只结算金钱与胜负的结局视为不合格**——纪实批判题材若结局只提"投资人亏了多少钱"，会把一场伦理灾难降格成一次商业事故。结局仍用全知旁白（不是第一人称），它要收的是所有人的账。
  - **闸门题至少 1 道落在受害者或代价上**（不能六道题全是"哪个高管干了什么"）。
- **故事页签**：主界面第一个页签（但不是落地页——落地页是情节卡）。左侧目录按卷列出**开场**与过关后的**各页回顾标题**；正文即图文长廊（左图右文）。开场左侧只用开场图一张；回顾每页可点目录或「下一页」顺序阅读。未开启的卷不出现。
- **玩法说明**：3~4 页翻页弹层，顶栏「玩法说明」按钮随时手动打开（不自动弹出）。**写成纯操作说明**（"每张情节卡都留着人名与地名的空"），不要把玩法包装成一个虚构身份的活计（"你是拾遗人，你的活计是……"）——身份框架一旦进了界面，故事层的第四面墙也就守不住了。
- **常驻提示**：顶栏「提示」唯一入口，按当前状态推导"下一步做什么"，每条可一键跳转；必须有通用兜底，永不为空。
- **存档**：localStorage 自动存档，标题页可「继续游戏」。
- **统计与收集率**：错误/提示/休整/用时/各卷星级/总分，结局屏展示。

### 4.8 美术与图像（全量绘图 · 定妆照 · 三处应用）

图像是这类「档案式」游戏沉浸感的核心，必须**成体系地全量生产**，不能只给人物画头像。技术规格（尺寸/清晰度/格式/生图接口）见 doc/04-art-pipeline.md，本节讲设计约束。

- **全量绘图（硬性覆盖规则）**：
  - **人物**：统一风格的头像（1:1），并为每个反复出场的人物先写一张**定妆照**——用详尽稳定的语言固定其外观、服饰、配色、气质、标志物。
  - **地点 / 物品 / 概念**：**每一个词条都必须有一张图（1:1）**。地点画其标志性环境，物品画静物特写，**概念画能象征该抽象概念的意象**（如「轮回」画陶匠的旋轮、「唵」画以心为箭指向梵天的意象、「涅槃」画苦海彼岸的宁静），不得留空。
  - **情节卡**：**每一张情节卡都必须有一张 16:9 的 CG**。
  - **作品主题图标**：**每部作品必须有一枚 1:1 主题图标**（情节列图标），见下方专条。
- **作品主题图标（情节列图标 + favicon，硬性规范）**：
  - **每个游戏图标不同**：根据该作的**主题、意向、情感特点**设计一个单一、聚焦的核心意象（实例：悉达多 = 金色晨河上泛起同心圆涟漪的渡船与一片菩提叶——倾听与安宁；坏血 = 冷青实验室辉光里悬在纳米采血管上方的一滴血——精致的骗局）。
  - 规格：**1:1、1K、low、jpg**，使用 `Lumi/Lumi_API_gpt-image2-tencent.py` 生成（emblem 徽章式居中构图，无文字）；生成脚本 `tools/gen_scene_icons.py`（技术细节见 doc/04-art-pipeline.md）。
  - 应用一：**时间轴「情节列」列头**（尺寸与人物头像列头一致）。
  - 应用二：**中心裁切（88%）缩为 64×64 PNG 作为该作品的 favicon**（`assets.favicon`，运行时动态设置，替代全作共用的程序绘制兜底图标）。
- **情节卡 CG（规格与内核呈现）**：
  - 规格：**16:9、1K、low、jpg**（与全局美术规范一致）。
  - 内容：呈现该卡故事的**环境、人物、主要内容与情绪基调**。鼓励用**有特色的镜头/意象**表达其内核（以一件物、一束光、一个背影传递情绪），而非直白图解；**尤其避免「画面两边各站一个人对话」式的呆板构图**。
  - **人物一致性（定妆照铁律）**：CG 中出现的人物必须通过定妆照传递——① 在 prompt 尾部写清该人物的定妆设定描述；② 以该人物的**头像作为 base64 参考图（图生图）**传入生成接口。多个已知人物同框时逐一声明并各附参考图，保证跨图形象与画风一致。**故事跨度大、人物明显变老时**，为人物登记中老年等形象变体（`entries[].variants`，配变体定妆照与变体头像），按卡用 `cgCharVariants` 指定，让发色与容貌看得出岁月流逝（实例：悉达多第三关自「朝圣蛇咬」起改用老年版）。
  - **prompt 语言规范**：新写或重绘的 CG 画面描述（`cgPrompt`）与定妆照（`look` 及其变体）一律用**中文**撰写；`meta.art` 画风后缀维持英文模板不变。存量英文 prompt 不强制回译，重绘时一并中文化。
  - **不泄底**：CG 只呈现氛围与已知信息，**不得替玩家点破本卡待猜人物的身份**（对匿名 NPC 用背影/剪影/远景等不暴露长相的镜头）。
- **画风统一**：全作统一日式动画（anime）明亮清新风（京阿尼参考）；禁止照片写实风；禁止画面文字/水印。
- **图像的四处应用**：
  1. **档案**：词条详情页的 hero 图——人物用头像，地点/物品/概念用其档案图。
  2. **词条库**：**地点卡**用其图片作为卡片（entry-card）的**背景图**——图上叠一层**由浅到深的暗色渐变遮罩**，并**调整文字样式**（白字 + 深描边，或加衬底）确保词条名与简介清晰可读（浓度可按项目基调取舍：从"淡化只起氛围"到"图为主"皆可，但**文字必须始终清晰**；成稿须实机截图自检）。物品/概念卡不做背景图。
  3. **情节卡**：该卡**验证通过（补完）之后**，在其正文顶部展示对应的 16:9 CG（未补完前不展示，避免提前剧透）。
  4. **时间轴格子**：补完的卡放入时间轴格子后，其 16:9 CG 铺满整格作底色（标题压深色渐变白字，见 §4.4）。

### 4.9 回顾本关故事（多页图文长廊）

玩家花一整关把碎片拼回去，拼完手里是几十张卡，脑子里却未必有一条完整的线。这个功能把那条线还给他。

- **解锁与入口**：某关的**情节列整列归位锁定**后（或该关已通关），时间轴中列底部出现「📖 回顾本关故事」按钮。只读回顾旧关时恒可用。
- **形态**：全屏覆盖层，多页翻阅。每页左右各占约半屏（窄屏改上下）：
  - **左 · 综合预览图**：本页覆盖到的情节 CG / 角色卡图，主图铺满 + 每 4.5 秒交叉淡入自动切换，底部小图条**水平居中**、可手点定格。默认取覆盖卡中**已补完**卡的 CG（未补完的不露，防剧透）；也可在数据里显式指定 `images`。
  - **右 · 故事回顾文章**：第三方旁白口吻的连续文章，以旁白为主，夹**少量**最重要的对话（引语气泡，带人物头像）。
  - 长廊近乎铺满屏幕（上下只留极窄边距，这是要沉下心读的东西）；头部只有「第 N 关 · 故事回顾」与本页标题；**最后一页的「下一页」变成「关闭」**，读完顺手就能出去。
- **页数（硬性）**：`页数 = int(时间段数 × 0.5 + 0.5)`，且**必须 < 时间段数**。6 行 → 3 页，5 行 → 3 页，8 行 → 4 页。
- **行区间（硬性）**：每页覆盖一段**连续**的时间行；各页互不重叠；合起来**恰好铺满整关**。覆盖卡默认就是这些行上的全部卡（情节列 + 角色列）。
- **字数（硬性）**：每页文章字数 = 该页**覆盖卡正文总字数的 10%~20%**。这是"回顾"而不是"重讲"：超过 20% 就成了复读，低于 10% 会漏掉半数事件。
- **写法**：
  - 全知旁白、过去时态，以事件推进为主线；角色列的独白/对话卡贡献动机与内心，情节列的卡贡献主干。
  - **不是逐卡复述**，要重新组织成一条有因果、有轻重的叙述线；每张覆盖卡的核心事件都要有着落。
  - 人名一律写真名（不写 NPCn）。
  - 与 §4.7 同一条纪律：**不对玩家说话、不用第二人称、不出现玩法词汇**。
  - 引语每页 1~2 条封顶，尽量化用卡面已有的台词，不凭空编。
- **生产**：`tools/init_recaps.py` 按公式切好页、算好覆盖卡与目标字数区间，产出 `workspace/{作品}/DEBUG/recaps.json` 当写作任务书；写完用 `tools/apply_recaps.py` 合并进 `final_game.json`。游戏内可用 DEBUG「故事回顾」编辑器直接改（页数、行区间、覆盖卡、逐段文字，字数区间实时显示）。

### 4.10 背景音乐（BGM）

音乐是玩家在几十张卡之间唯一连续的东西，所以它要先于一切服从「故事」。技术细节与 skill 见 [doc/14](doc/14-bgm-pipeline.md)；实例 `workspace/xidaduo/DEBUG/BGM_DESIGN.md`。

- **旋律为主、有记忆点、与故事匹配（硬性）**：先写「音乐圣经」——主题一句话、全作基调、乐器调色盘、**一段全作统一动机**（4–6 音的旋律乐句，起名）。每一首都以不同乐器 / 速度 / 调式复现或变形它；每关另定一句「本关定位」。纯器乐，无人声。
- **重要人物有专属音乐记忆点（硬性）**：`core/major` 人物各绑一种乐器（或流派 / BPM），人物之间不得重复；在该人物的独白卡 / 名场面卡的曲子里点名使用。
- **每关一首开篇曲（硬性）**：`stage=关号` 且无 `unlockCard`，恰 1 首，由过场与本卷之问的情绪出发写；进关时歌单清空、只播它。
- **每关曲数 = `max(round(本关情节卡总字数 / 1500), 2)`，含开篇曲（硬性）**；另有封面曲、结局曲各 1。`python tools/bgm_plan.py <作品>` 直接算。
- **分配（硬性）**：卡曲绑「名场面」列或独白卡（重要情节 / 人物独白），按时间轴 `row` 逐行铺开，每行至多 1 首，让音乐沿剧情线均匀出现；不绑 `startUnlocked` 卡。
- **辨识度（硬性）**：同关任意两曲在「主奏乐器 / BPM（差 ≥ 15）/ 调性明暗」中至少两项不同；曲名 ≤ 6 字。
- **流程**：六条全部落成 `assets.bgm`（每条含 `prompt/tags/note`）并通过 `validate_data.py` 之后，才 `python tools/gen_bgm.py <作品> --clean` 一次性并发生成；换单曲用 DEBUG「背景音乐」（复制 prompt / 更换音频），不在游戏内重生成。
- **玩家侧**：进关只有开篇曲；补完绑定卡即解锁新曲、切过去播、播放器亮金色光效；往期曲在菜单「往期曲目」里可点播或临时勾进本关歌单。

## 5. 内容生产管线（从故事到数据）

0. **原著取材（改编作品第一步，不可跳过）**：把原著全文放进 `workspace/{作品}/book/`，先产出 `DEBUG_book_report.md`——章节概括（含年份）、人物表（**以译本实际译名为准**并附原文名）、事件时间线、关键地点、关键物品与概念、主题与悬念点、金句清单（标注章节）。**之后每写一张卡都要回原文/报告取材**，卡表的"内容要点"标注取材章节；写作时优先用原著自带的细节与金句，别凭印象编。**原著没有的原创补充一律在设计稿里标 `【演绎】`**（如把"斯坦福同学"写成"同寝室友"），否则后人会把演绎当考据继续放大。
1. **剧情考据**：人物表（含别名、关系、结局）、事件时间线、关键物品、易错细节（谁杀了谁、谁是谁的谁），交叉核对原文。
2. **切卷与定轴**：按时间切 3 卷；每卷定时间段（行）与列（情节列 + 各卷活跃人物）。**先用时间轴四条密度规则算网格**：行数 × 角色列数 × 45% ≈ 需要的人物卡数，据此反推行数，别贪行。关卡难度递增，第一关时间段（行）为4~6行，之后每一关比前一关增加1~2行，但不超过10行。
3. **拆卡与定档**：把事件拆成 40~60 张卡，标好形式、出场人物、**难度档与字数档（len S/M/L）**——先定档再写作（见 §4.1 字数量化）。分配难度：独白卡天然入「简单」；多人名场面/高潮戏入「困难」（≤20%）。
4. **匿名化写作**：要猜的人物写 NPCn，时空写模糊；把词条以 `{{词条|显示名}}` 织入正文。**纪律：答案真名不得出现在本卡正文**（chip 或裸文本），剧情特许例外登记白名单。**同卡多人空逐一给差异化识别点**（可推理性，见 §4.1）。对话气泡化、同卡人名 chip 唯一、有对话的非匿名人物必配 chip（见 §4.1/§4.2）。
5. **定地点**：按故事**实际发生的小地名**设置（"XX 的家/那片小丘"，不要"北京/中原"）。**一卡多地必做数组答案**：一张情节卡可能涉及多个地点（角色移动、电话/通讯两端各在一处、多线并行等），此时地点空的正确答案必须是数组，**所有在本卡被涉及（有人物身处其中/情节实际发生）的地名都视作正确答案**（玩家选任一即对）；仅在对话中被顺口提及、无人身处的地名不算。注意数组成员同样受匿名铁律约束（真名不得出现在本卡正文）。每个地点在正文至少留 1 处可点 chip。
6. **核算词条**：列全词条表，逐卷算各词条的熟悉度来源（tag 卡 + 答案卡）；确保每个空位答案都有收集路径（chip 或起始词条）。**逐词条标 `tier`（core/major/minor）并按分层规格核对 desc 与档案字数**（见 §4.2）；**核对受害者覆盖**：纪实题材至少 2 名直接受害的普通人做成词条 + 档案，其中 1 名进角色列。**逐词条核对"创建必使用"**：每个词条在其登场关内要么有档案页可分析（上限可 =1），要么被其他卡提及或作为空位答案（上限 ≥2），两者皆无的词条删除或合并。**核对角色重要度**：主角的单关熟悉度上限应明显超过配角（群像戏也不例外），若拉不开差距，回头给主角补 tag/答案来源。**注意"签与答案冲突"**：指定的必织词条若恰是本卡答案，换成同场其他词条；**注意卷内自洽**：过关后看不到上卷卡，本卷答案与档案解锁所需的词条必须在本卷内可获得。
7. **档案与闸门**：核心人物多页档案分卷解锁；完形填空的答案必须都能在本卷达成候选条件。**先列「问题-答案对照表」再写题**：全作之问（`meta.tagline`）、各卷之问（`gates[].question`）、每卷题面、回顾末页、结局回应五处逐行对应；每卷 ≥3 道题标 `revealAt:"start"` 且题面不含本卷待猜真名、不点破结局；过场按 §4.7 规格写（恒 5 段、本卷主角第一人称、第 1 卷两问套叠、末段落成本卷之问并接上首卡）；第 1 关开局解锁 2 张卡并核对「填 / 搜 / 收」链（见 §4.1 首卡规则、§4.5、§4.7）。**写完统一查留白答案分布**（单答案 ≤12% 且 ≤5 次、同页不重答案、去重率 ≥60%、四类词条都要问，见 §4.3）；闸门题至少 1 道落在受害者/代价上。
7b. **回顾本关故事（见 §4.9）**：跑 `tools/init_recaps.py` 生成分页骨架（页数按公式、行区间连续铺满、覆盖卡与目标字数自动算好），逐页写第三方旁白口吻的回顾文章，字数守住覆盖卡总字数的 10~20%，再用 `tools/apply_recaps.py` 合并。
8. **美术（全量绘图，见 §4.8）**：统一风格的人物头像（1:1）+ 定妆照；**每个地点/物品/概念词条一张图（1:1）**（概念画象征意象）；**每张情节卡一张 16:9 CG**（用定妆照 base64 参考图 + prompt 设定描述保证人物与画风一致，避免两人对站的呆板构图）；**作品主题图标（1:1，按主题/意向/情感设计，兼作情节列头与裁切 favicon）**；标题/结局图、剪影。四处应用（档案 hero / 地点词条卡背景 / 补完后情节卡顶部 CG / 时间轴格子 CG 底图）见 §4.8。
8b. **音乐（见 §4.10 / [doc/14](doc/14-bgm-pipeline.md)）**：正文定稿后跑 `tools/bgm_plan.py` 得每关曲数；写音乐圣经（全作动机 + 人物动机表）与每关曲目表进 `DEBUG/BGM_DESIGN.md`，把全部条目（开篇曲 + 逐行铺开的卡曲 + 封面 / 结局曲，各带英文 `prompt`）写进 `assets.bgm`；`validate_data.py` 通过后 `tools/gen_bgm.py <作品> --clean` 一次性并发生成；试听后单曲用 `--only <id> --force` 或 DEBUG「背景音乐」换备选。
9. **质检与试玩**：见第 6 节。悉达多另有五语叙事包：简体仍是唯一可写真源，译文在 `workspace/xidaduo/i18n/`，专名与不译字段见该目录 `STYLE.md` / `glossary.json`，管线见 [doc/13](doc/13-i18n.md)。字数红线只跑简体。

## 6. 质量检测（必须工具化，不靠肉眼）

本模板的数据校验器（`tools/validate_data.py`）就是设计红线清单，改数据后必跑。
校验分**两档严重度**（见 §9）：**完整性错误**任何时候都拦；**设计规范**在作品标记完工后降级为建议。下列条目除
「Schema」「可收集性」「熟悉度可达」「自动通关模拟」「回顾的结构性检查」外，都属于设计规范档。

- **Schema**：必填字段、类型、引用存在、时间轴坐标唯一、每卡 ≥1 个词条标签、空位答案类型匹配、档案留白答案存在且类型匹配。
- **时间轴内容量**：每行 ≥2 卡、情节列每行恰 1 张、每个角色列 ≥2 卡、角色列填充 >40%（见 §4.4）。
- **字数量化**（meta.cardSpec.avg 存在时）：每卡 len 必填 S/M/L，S ∈ [58%,75%]X、M ∈ [85%,115%]X、L ∈ [120%,150%]X、全卡平均 ∈ [92%,108%]X（见 §4.1）。
- **难度一致性**：`简单`卡不得有地点空；`困难`卡不得有已知发言人（speakerEntry）。困难卡的"不许露名"只针对本卡待猜的人，由匿名铁律统管，不再另外禁止人名标签。
- **对话呈现**：同卡同人物 chip ≤1 次；具名发言人（speakerEntry）卡内必有可收集 chip；配角 `speaker` 文本名非空且不得与人物表角色重名（重名说明该用 speakerEntry）（机械检查）。对话气泡化本身靠复查：逐卡扫旁白段中的「」，对照 §4.1 的例外清单确认可留旁白者。
- **匿名铁律**：空位答案的真名不得以 chip 或裸文本出现在本卡正文（白名单除外）。
- **可收集性**：每个空位答案（含数组任一）必须在某卡正文中可点，或在起始词条中。
- **熟悉度可达**：有档案页的词条，在该页所在卷必须有熟悉度来源。
- **重要度分层规格**（写了 `tier` 的词条强制）：desc 字数、档案页数、每页字段数、字段正文字数下限、每页留白数按 core/major/minor 分层校验（见 §4.2）；任何字段正文 ≥8 字。
- **留白答案分布**：单个词条被引用 ≤12% 且 ≤5 次、同页留白不得同答案、同词条跨页 label 不重复、全作去重率 ≥60%（见 §4.3）。
- **一事一卡（重复片段）**：任意两张卡正文若有 ≥20 字连续重合，或同一条 ≥12 字台词（去标点后完全相同）出现在两张卡 → 报错（见 §4.1）。
- **弧光断线**（警告级）：某人物在第 N 关与第 N+2 关都有来源、第 N+1 关无任何来源 → 警告，提示补过渡卡（见 §4.1）。
- **故事框不对玩家说话**：`frame` 的旁白不得含第二人称（你/您/玩家）；全部 frame 文本不得含玩法词汇（残页/页序/拼回/归位/词条/时间轴/完形填空/活计……）；`meta.subtitle` 与 `ending.credit` 不得含身份词（拾遗人/档案修复员……）；结局 ≥8 段（见 §4.7）。
- **过场规格**：每卷过场恰 5 段（首段为 ≤16 字的「第N卷 · 名字」卷名段 + 4 段正文）；正文每段 60~130 字（越界为警告）；第 1 卷正文含 ≥2 个「？」（全作之问 + 本卷之问，警告级）（见 §4.7）。
- **悬念前置**：每卷 `gates[].question` 必填、以「？」结尾、≤30 字、无第二人称与玩法词汇；`meta.tagline` 若有同规则；每卷 `revealAt:"start"` 的题 ≥3 道且题面不含本卷任何空位答案的词条名；每卷过场末段含「？」（警告级）；第 1 关 `startUnlocked` 恰 2 张（警告级）（见 §4.1 首卡规则、§4.5、§4.7）。
- **过场写法复查**（不可机械校验，成稿必查）：①正文是否全程本卷主角（或合规见证者）的第一人称、视点是否换手；②第 1 段正文有没有人、有没有事，是否拿气氛/结局意象开场；③问句里点到的人是否都已登场；④末段场面是否接得上本卷首卡；⑤有没有留白，还是把戏演完了；⑥第 1 段正文与底图是否同一时空（见 §4.7）。
- **回顾本关故事**（写了 `recaps` 才查）：页数 = int(行数×0.5+0.5) 且 < 行数；各页 rows 为连续区间、不重叠、恰好铺满全关；每页字数为覆盖卡总字数的 10~20%；引用的卡属于本关、引语词条存在（见 §4.9）。
- **自动通关模拟**：贪心 bot 证明三关可通关、体力不为负、闸门候选池可达（进度 = 归位×25 + 档案×10）、档案留白答案均可收集。
- **界面与流程**：Playwright 冒烟/状态基线用例 + 全正确答案真实点击的通关 bot（数据驱动，自动适配新故事）。
- **可推理性**（不可机械校验，靠复查）：成稿后逐卡以"没读过原著的玩家"视角复核——每个空是否可唯一推出、同卡多人空是否有差异化识别点（没有提示文案兜底，正文本身必须给足识别点）。
- **词条使用与重要度**（设计复查）：逐词条核对"创建必使用"（登场关内可分析档案，或被提及/作为答案，见 §4.2）；核对主角单关熟悉度上限明显超过配角，避免群像戏无重心。
- **人物塑造复查**（不可机械校验，成稿必查）：①暧昧人物是否被写成"自知的阴谋家"（独白里有没有作者判词）；②立场反转的人物有没有过渡铺垫、动机是否延续原著；③受害者是不是只当了背景板（有没有词条、档案、角色列）；④结局四件事（事实/代价/主题/框架）是否齐备，有没有退化成只结算金钱。
- **取材复查**：抽查 10 张卡，核对其细节能在 `book/` 原文或 `DEBUG_book_report.md` 里找到出处；原创演绎是否都在设计稿里标了 `【演绎】`。

## 7. 踩过的坑与规避（实测教训）

1. **地名太粗、来源太少**：曾用一个大部落名填 23 张卡，且只有 1 处可点，玩家翻遍残页也拿不到。规避：地名具体到"谁的家/哪个山坡"，每个地点正文至少 1 处 chip；一卡多地用数组答案。
2. **熟悉度一次攒满、终身有效**：主角第一卷满级后，熟悉度系统在后两卷失效。规避：分关清零重攒，收集与档案继承。
3. **为最后 1 点熟悉度穷举全卡**：曾用"≥3 来源时上限打 80% 折扣"缓解，实测反而让数值含混、体验不佳，已回退为**上限 = 本关来源数**。规避方向改为：设计时保证词条来源充足、分布合理（搜寻优先级也会把相关卡先发给玩家）。
4. **100% 才能开闸**：最后两张卡/两页档案的追逐极其挫败。规避：70% 开闸 + 进度条可视化 + 100% 解锁「自动填写」退路（只填草稿不提交、不影响评级）。
5. **完全随机发新卡**：玩家连翻无关卡，拿到的人名对不上手头的卡。规避：搜寻优先级按「回答>收集」分层——"可立即完美作答"的卡恒优先于"可预期作答"的卡，再优先于纯收集价值的卡；词条库红点直接把最佳搜寻目标指给玩家。
6. **卡片只剩"自指"标签**：一张卡的唯一词条 chip 首次出现在它自己正文里，它就永远无法被搜寻解锁。规避：每卡至少一个"别处已能获得"的标签，校验器拦截。
7. **档案页答案无来源**：某词条只在一处出现，被匿名化改写顺手删掉后，档案留白永远无法填写。规避：校验器对每个档案答案做可收集性检查。
8. **横向候选条**：十几个候选横排难找难看。规避：居中弹窗 + 人物三列大图卡 / 地名物品三列紧凑卡 / 标题单列。
9. **新卡随机散落进时间轴格子**：格子又满又乱，对错无感。规避：独立「待归位区」，格子只放玩家亲手放入的卡。
10. **放错给惩罚/强提示**：玩家畏手畏脚或被提示剧透。规避：放错零成本、不打扰，提示只给绿线和行列扫光。
11. **教学与常驻提示缺席**：系统叠了五六层，没有引导玩家必弃坑。规避：首卡聚光教学 + 永不为空的顶栏提示。
12. **让词条库兼顾一切入口**：按钮越堆越多。规避：词条库只留「搜寻」，「分析」放档案界面。
13. **「签与答案冲突」**：设计稿指定"本卡必织词条"时，发现它恰是本卡答案（铁律禁止）。规避：先列答案再定签；冲突时换同场其他词条。
14. **卷外依赖**：过关后看不到上卷的卡，若本卷答案的词条只在上一卷出现，卡就永远填不了、档案永远开不了。规避：每卷"答案候选与档案解锁"必须卷内自洽（可用伏笔 chip 预置下卷词条），校验器按卷检查收集路径。
15. **时间轴人物列稀疏**：按"一行一情节卡"自然摆卡，人物列填充只有 30% 上下，时间轴既空又少推理支点。规避：四条密度规则（行≥2、情节列满、列≥2、填充>40%）写进校验器；设计时先算网格再拆卡，人物独白/对话卡是"密度调节器"。
16. **点击"看起来无效"**：熟悉度已满时点词条毫无反应，玩家以为坏了。规避：打勾与熟悉度自增解耦——已满仍记"本卡已点"并显示 ✓，自增才封顶。
17. **逐条上屏时自动滚到底**：新内容不断把用户刚读到的位置顶走。规避：不自动滚动，用户不碰就停在顶部。
18. **同一件事写了两张卡**：坏血初版把"闺蜜赴海外项目撞见造假 → 回来找创始人对质 → 被一句'公司是最重要的'打回 → 用'搬去洛杉矶'的理由辞职"整条链，在情节列卡和角色列卡里各讲了一遍，连金句和辞职理由都一字不差。玩家读第二张只有既视感，而原著整整一章的营销包装内容因为没卡位而完全没进游戏。规避：一事一卡（§4.1），角色列卡必须给新事实/新视角/新后果；校验器查 ≥20 字重合片段。
19. **把暧昧的反派写成自知的阴谋家**：给主角写了"故事只要动人，就是真的""接下来只需要让机器也相信"这类第一人称自白，原著里作者始终不肯下的定论，被游戏一句话说破，人物立刻扁平。规避：独白只写她自己相信的逻辑（§4.1）。
20. **受害者只当配角气泡**：病人、家庭医生只用 `speaker` 出现两三次，没有词条、头像、档案；而只在一章露脸的高管却有完整档案页。系统层面等于宣布"受害者不重要"，成品味道变成上流社会宫斗。规避：受害者必须进词条系统并进角色列（§4.2），结局与闸门题都要有代价结算（§4.7）。
21. **档案留白全在问主角**：44 处留白有 9 处答案是同一个主角，档案系统退化成点名。规避：留白答案分布规则（§4.3）写进校验器。
22. **给玩家安排身份、在故事框里派活**：四部作品的过场一度都是同一套结构——一位框架长者（老商人/守屋老人/老编辑/老馆员）把"残稿"交给玩家，说"人名被虫蛀了、页序乱了，你把它补回来"。三个后果：①故事第一句话就在讲玩法，纪实题材的重量与原著语气全被冲淡；②每换一部作品都要重写一遍派活台词，纯属重复劳动；③玩家真正需要的操作说明其实在 UI 层，故事框里的那套说明只是噪声。规避：故事文本只讲故事（§4.7），身份词从 `subtitle`/`credit` 里一并清掉，操作说明交给「玩法说明」弹层与常驻提示；校验器机械拦第二人称旁白与玩法词汇。
23. **开篇九屏、四屏不见人、问的人没登场**：一部文学改编的第一卷过场写成九段全知旁白：前三段是听水声、看风景的气氛铺陈，还把原著结局的意象搬到开头当钩子；真正出事的场面压到第七段、一句带过；叙述者三次换手（气氛旁白→年代交代→人物→旁白）；末段问的是全作之问，下一屏引擎亮出的本卷之问却问"两个人为什么分开"——而第二个人在过场里一个字都没出现。玩家点了十一下才进游戏，手里拿着一个追不了的问题。规避：过场恒 5 段、本卷主角第一人称、第 1 段就有人有事、第一卷两问套叠、问句点到的人先登场、末段接首卡、留白（§4.7）；校验器拦段数与卷名段、警告段长与首卷问号数。

## 8. 设计红线速查（贴墙用）

- 填写一律点选，**永不打字**。
- 人物对话**一律气泡**（动作写括号）；**纯配角也用气泡**（`speaker:"名字"`，淡色首字印章，不配头像）；旁白只留例外：群体台词/诗歌/回顾引语/悬念身份/困难卡登场但未设空者。
- 同卡同人物 chip **至多一次**（置于首次登场处）；有对话的非匿名人物**本卡必有 chip**。
- 答案真名**永不出现**在本卡正文（白名单登记除外）。
- 同卡多人空，**每人必须有差异化识别点**（可推理性）；卡内没有提示文案，识别点只能来自正文。
- 难度：简单 ≈30%（无地点空）、困难 ≤20%（**登场人物**全匿名、无 speakerEntry；正文仍可提及不在本卡待猜之列的第三方人名 chip）。
- 字数：平均 X（默认 700）±8%；S=60–70%X、M=85–115%X、L≈130%X，**先定难度与字数档再写作**。
- 语言：**现代通俗白话**，不文白夹杂。
- 时间轴密度：**每行 ≥2 卡、情节列每行恰 1 张、角色列各 ≥2 张、角色列填充 >40%**。
- 角色列的卡，**列主人物必须是本卡的 NPC1**。
- 地名小而具体，正文必有 chip，**不开局赠送**。
- 一卡涉及多个地点（移动/通话两端等）时，地点空答案**必须列全为数组**——所有本卡实际发生地都算对。
- 熟悉度**分关清零**，上限 = 本关来源数（无折扣）；**点击打勾与熟悉度自增解耦**（已满也能打勾）。
- **词条创建必使用**：每个词条在登场关内，要么有档案页可分析（上限可 =1），要么被其他卡提及/作为空位答案（上限 ≥2）；两者皆无的"死词条"删除或合并。
- **角色重要度分层**：群像戏也要有明确主配角之分，主角单关熟悉度上限须**明显超过**配角。
- **词条分三层 `tier`**：core（3~6 个，desc 30~60 字、跨卷 ≥2 页、每页 5~6 字段 ≥2 留白）／major（12~20 个，desc 20~40 字、1~2 页、每页 4~5 字段 ≥1 留白）／minor（其余，desc 12~30 字、可无档案）；**任何档案字段正文 ≥8 字**，禁止"职位：CFO"式标签。
- **受害者进系统**：纪实改编至少 2 名直接受害的普通人做成人物词条 + 档案页，其中 ≥1 名进角色列；`speaker` 只留给一次性功能角色。
- **留白答案分布**：单答案 ≤12% 且 ≤5 次、同页不重答案、同词条跨页 label 不重复、去重率 ≥60%、四类词条都要问。
- **一事一卡**：同一事件只占一张卡；角色列卡与情节列卡重叠时必须给新事实/新视角/新后果，**金句与结局细节不得复述**。
- **暧昧人物不自白**：加害者独白只写自我合理化，不写作者判词；立场反转必须有过渡卡铺垫，动机延续原著。
- **过场与结局只讲故事**：**不给玩家安排身份、不由框架叙述者派活、旁白不用第二人称、不出现玩法词汇**（操作说明放「玩法说明」与常驻提示）；`subtitle`/`credit` 不挂身份词。
- **过场规格**：每卷**恰 5 段 = 卷名 + 4 段正文**，正文每段 60~130 字；正文用**本卷主角的第一人称**（加害者不自白，改见证者；原著第一人称则沿用叙述者），一卷之内**视点不换手**；第 1 段正文就**有人有事**（不拿气氛、风景、结局意象、抽象概念开场）；**第 1 卷立两个问题**（前两段抛全作之问、末段落本卷之问，两问套叠），其他卷只在末段落本卷之问；问句点到的人**先登场再被问**；末段停在本卷首卡的门口；**留白**（不解释动机、不下判词、至少一处「我不知道」）；第 1 段与底图同一时空。
- **结局规格**：≥8 段、全知旁白，齐备事实/代价/主题/**余响**四件事；闸门题 ≥1 道落在受害者或代价上。
- **悬念前置**：`meta.tagline` = 全作之问（可选）；每卷 `gates[].question` = 本卷之问（必填，问句、≤30 字、不用「你」、无玩法词汇）；卷末题标 `revealAt`，每卷 ≥3 道 `start` 且不泄底（不含本卷待猜真名、不点破结局）；第 1 关开局 2 张卡（钩子正文版 + 覆盖「填 / 搜 / 收」）；开局卡首段不做科普。
- **问句与题面文风**：简单直白、一读就懂；不谜语、不堆修辞、不排比、不空泛抒情；照 `book/` 原著语气写。
- **改编先取材**：原著全文进 `book/`，先出 `DEBUG_book_report.md`，逐卡回原文取材，原创补充标 `【演绎】`。
- 单格放对**不锁定**：整行/整列凑齐 或 连片 ≥4 才锁；残页不参与计数。
- 闸门进度 = **归位×25 + 档案×10**，**70%** 开闸（界面只显示百分比）；题面开局可展开阅读（`gate` 题为「？？？」），70% 前无答案栏、不可填不可提交；关卡出口的关名 = 过场首段卷名（与「故事」页同源，闸门无独立关名字段）；自动填写只填草稿**不提交、不影响评级**。
- 行/列归位判定：行/列内**混入了放错位置的卡**则不得判定完全正确。
- 体力模拟**必须 0 休整通关**；任何数值改动后重跑通关模拟。
- 每卡 ≥1 个外部可获得标签；每个空位答案都有收集路径（**卷内自洽**）。
- **全量绘图**：人物头像 + 定妆照；**每个地点/物品/概念词条一张图**（概念画象征意象）；**每张情节卡一张 16:9 CG**；**每部作品一枚 1:1 主题图标**（情节列头 + 裁切 favicon）。CG 人物必用定妆照（base64 参考图 + prompt 设定）保持形象与画风，忌两人对站呆板构图，忌泄露待猜身份。
- **图像四处应用**：档案 hero；**地点词条卡用图作背景**（叠暗色渐变 + 白字深描边等确保文字始终清晰，实机截图自检）；情节卡**补完后**正文顶部显示 CG；时间轴格子内补完卡以 CG 铺底。
- 时间轴行头时间点名**默认隐藏**（「时间 N」+ 1 体力「提示♥」按钮）；整行归位自动揭示。
- **独白可覆盖人物行为**：原著里的大段行为描写改编为 **30% 行为 + 70% 自言自语/自我陈述**，仍算【独白】；不得退化成纯行为流水账，也不得借机写作者判词。
- **关卡带与只读回顾**：关卡带在右栏关卡出口上方，每格只给「第 N 关 + N 段情节」（不露关名与星级）；已通关的关可回看（不动进度、不清熟悉度），回顾时右栏必须留着好点回来；卡底居中一行 CG 缩略图做「上一节 / 下一节 / 同时段」跳转，未补完的目标不露 CG、只给虚框「？？？」。
- **回顾本关故事**：情节列整列归位后解锁；页数 = **int(时间段数×0.5+0.5)** 且 **< 时间段数**；各页行区间连续、不重叠、铺满全关；每页字数 = 覆盖卡总字数的 **10~20%**；第三方旁白为主、每页 ≤2 条引语；同样不对玩家说话、不出现玩法词汇。
- **使用者与时机**：`meta.status = "wip"`（缺省）时使用者是 AI，上面全部规范强制执行；标为 `"final"` 后使用者是内容总监，规范降级为建议——但**完整性错误任何时候都拦**（见 §9）。

## 9. 使用者与时机（规范什么时候是硬的）

同一条「简介 20~40 字」的规则，对两种使用者应该有两种力度：AI 在生产期会拿"差不多"当合格，必须硬拦；
人在成品期做一次有意识的微调，硬拦只会碍事。所以本套规范按**作品状态**分两档，写在数据里：

| `meta.status` | 使用者 | 设计规范 | 完整性错误 |
| --- | --- | --- | --- |
| `wip`（缺省） | **AI**（内容生产期） | **强制**，不达标不许保存、校验器退非零码 | 拦 |
| `final` | **用户 / 内容总监**（作品已完工，事后用 DEBUG 微调） | 降级为 **warning 建议**，不阻断 | 拦 |

**两类问题的界线（这条比档位本身更重要）**：

- **完整性错误**——违反了它数据就是坏的：引用不存在的词条/卡、时间轴坐标冲突或越界、schema 缺必填字段、
  空位答案类型不匹配、答案无收集路径、自动通关模拟通不过、回顾的行区间铺不满全关……
  **任何档位、任何模式都拦死**，因为放过去就是玩家卡关或白屏。
- **设计规范**——违反了只是"不够好"：字数档、`tier` 分层规格、留白答案分布、时间轴密度、一事一卡、
  故事框措辞、回顾字数占比……**受档位影响**。

**两侧行为一致**：

- 校验器 `tools/validate_data.py`：`final` 时把规范类以「建议:」打印后 exit 0；`--author` 强制严格（CI 恒用），`--director` 强制宽松。
- 游戏内 DEBUG 编辑器：`final` 时弹窗头部显示「内容总监模式 · 规范仅提示」徽标，规范类问题从 ✕ 变成 ⚠，不再禁用「保存并生效」。

**改档位**：DEBUG →「作品设置」里切换（切到 `final` 会二次确认）。作品没有真正完工前不要提前打勾——
一旦打勾，AI 后续再来改内容也会拿到宽松档，等于把生产期的护栏拆了。
