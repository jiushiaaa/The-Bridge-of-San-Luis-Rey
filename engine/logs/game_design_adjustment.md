# 开局钩子与谜题前置 · 设计调整方案

> 背景：作为一款「解谜游戏」，目前开局缺少「谜题」与「阅读价值」的传递——玩家不知道为什么要玩、能得到什么、要解开什么。
> 本文以 XDD（悉达多）为样例，分四部分：通用故事策划规则（可并入 README_game.md）、交互改造、引擎与数据改造、XDD 落地方案。
> 状态：**已按审核后的取舍实施完毕**（见文末「实施记录」）。下文 §1~§5 是审核前的原始方案，其中被否决 / 缩减的项目在实施记录里注明。

---

## 0. 现状诊断（XDD 新玩家前 3 分钟）

| 环节 | 玩家看到的 | 传递了什么 |
| --- | --- | --- |
| 封面 | 「悉达多 / 渡河人 · 一个求道者的一生」 | 题材说明，无悬念 |
| 第一卷过场（8 段） | 撑船人听河 → 回到婆罗门院子 → 沙门路过 → 少年站一夜、父亲让他走 | 有倒叙钩子，但**没有落成问题**，末句是句号 |
| 落地「故事」页 | 把刚读过的过场再摆一遍 | 零增量 |
| 新手引导四步 | 四个页签各是什么 | 讲工具，不讲目的 |
| 「你的目标」弹窗 | 「把打散的故事拼回来 / 1-获取情节 2-整理档案 3-填时间轴」 | 讲流程，不讲谜题与收获 |
| 首卡「婆罗门之子」 | 首段是种姓制度科普；NPC1 唯一候选就是开局赠送的悉达多 | 课本式开场，无推理 |
| 本卷真正的谜题（卷末五问） | 藏在时间轴右栏，题目 70% 进度后才可展开 | **玩了 40 分钟才看见自己在回答什么** |

三个错位：**钩子没有变成问题**；**谜题在流程末端**；**收获不可见**（CG、标题、画卷、回顾都在补完之后才出现，开局没有预告）。

XDD 特有问题：《悉达多》没有「谁干了什么」的悬案，张力全是内在的「为什么 / 怎么」。谜题必须写成「他为什么走」「是什么叫醒了他」「他听见了什么」，而不是「NPC1 是谁」。

## 1. 【设计理念 · 故事策划】通用规则（逐条，剥离具体故事，供 README_game 收录）

核心理念一句话：**从「拼图」转向「带着问题的阅读」——谜题先于材料，收获先于劳动。**

### 1.1 三层问题结构（硬性设计规则）

每部作品必须显性地设计三层问题，层层分解：

1. **全作之问**（1 句）：整部作品用一个问句概括的核心悬念。答案就是整部故事。
   - 要求：以「？」结尾；≤30 字；只用故事内的事实提问，不泄露过场之外的情节；不含玩法词汇。
   - 提问对象是**故事本身**（「一个 X 怎么会变成 Y？」「那一夜到底发生了什么？」），不是玩家。
2. **本卷之问**（每卷 1 句）：该卷的核心悬念，是全作之问的一个阶段性分解。卷末完形填空的每道题都应是本卷之问的一个碎片。
   - 要求同上；三卷的问句读下来应当能连成全作之问的推进（如：为什么走 → 什么叫醒了他 → 他听见了什么）。
   - 本卷之问的答案必须在本卷内可得（对应卷末闸门能答出）。
3. **每卡之问**：现有的 NPC / 地点空位，不变。它是把本卷之问拆到分钟粒度的手段，不是目的。

### 1.2 过场必须「以问句收尾」（在现有「开场必须有钩子」基础上加严）

- 每卷过场（`levelIntro[N]`）已要求先甩钩子再回到起点；现在加一条：**最后一段必须把钩子落成一个问句**，且这个问句就是本卷之问（可以是原句，也可以是故事化的变体）。
- 问句必须留在故事世界里：由故事内人物问出（「有人问那位撑船人……」）、或由全知旁白以「无人知道……」「没有人说得清……」的方式抛出；**不得**用第二人称、不得出现玩法词汇（延续 §4.7 纪律）。
- 第一卷过场的问句同时承担全作之问的首次亮相；后两卷的问句只需承担本卷之问。
- 反例：末段是一句陈述（「天亮时父亲让他走。」）——画面完整，但玩家没有被交给任何要去解开的东西。

### 1.3 卷末问题（完形填空）重新定位为「本卷谜题清单」

- 卷末 5~6 道题**不再只是过关考试**，而是本卷一开始就贴出来的「要搞清楚的几件事」。写题时按「一开始就会被看见」来写。
- 每道题必须标记**可见时机**：`开局可见` / `开闸后可见`。
  - 开局可见的题面**不得泄露本卷走向**：不得含有本卷任何待猜人物、地点的真名；不得直接说出某人物的结局或立场反转（「皈依僧团的是」→ 泄露了有人皈依）。
  - 泄底的题要么改写成不泄底的版本（「两人中，留在祇园的是谁」→ 仍泄；改为「听法之后，两个朋友做出了不同的选择——留下的是谁」），要么标为开闸后可见。
  - 每卷**至少 3 道题开局可见**，否则清单不成立。
- 题面写法从「考察记忆」转向「提出悬念」：用「谁 / 什么 / 哪里」把悬念挂起来，而不是复述情节再挖空。好题面读起来像悬念，答完像揭晓。
- 延续既有规则：至少 1 道落在受害者或代价上（纪实题材）；对内向型文学作品，改为至少 1 道落在「主角内心转折」的具象物（一个字、一件物、一只鸟）上。

### 1.4 首卡规则（玩家读到的第一张卡）

- **首卡必须是钩子的正文版**，而不是背景交代。过场里抛出的那个场面（站一夜的少年、太完美的演示、靠岸的橡皮艇），玩家读的第一张卡就应当是它，或直接延续它。
- 首卡第一段**不得是世界观 / 制度 / 历史科普**；必要背景挪到第二段之后，或织进后文旁白。
- 开局解锁 **2 张**卡而不是 1 张：一张情节卡（钩子场面）+ 一张独白或对话卡。两张合起来至少提供：一个用开局赠送词条就能填的空（教「填」），一个必须去搜寻才能填的空（教「搜」），一个有对话的人物 chip（教「收」）。
- 开局赠送词条（`levelStartEntries`）只给「问题里已经点名的人」——问句里出现了谁，谁就可以送；没被问到的人不送，留给搜寻。

### 1.5 封面副标题与题记

- `meta.subtitle` 继续做类型 / 题材说明（不挂身份词，延续现规）。
- 新增 **题记 `tagline`**（1 句，可选）：就是全作之问本身或其故事化变体。不泄露过场以外的情节。有题记的作品，封面上先看到问题再看到「新的开始」。

### 1.6 收获的可承诺性（内容侧的对应要求）

- 每卷的「本卷之问」要能在**过关那一刻被明确回答**——卷末回顾长廊（§4.9）的最后一页必须正面回应本卷之问（不复述，而是让读者读到答案）。
- 结局四件事（事实 / 代价 / 主题 / 余响）之外，加一条：**结局至少有一段正面回应全作之问**。
- 全作之问、三个本卷之问、卷末题面、回顾末页、结局回应——这五处必须互相能对上号，写作时列一张「问题-答案对照表」放进设计稿。

### 1.7 校验与自查清单（策划侧）

- 全作之问 1 句、本卷之问每卷 1 句，均以「？」收尾、≤30 字、无第二人称、无玩法词汇。
- 每卷过场末段含问句，且与本卷之问同义。
- 每卷卷末题 ≥3 道开局可见；开局可见题面不含本卷待猜词条真名。
- 首卡第一段非科普；开局解锁 2 张卡，满足「填 / 搜 / 收」三教学点。
- 回顾末页与结局各有一段回应对应层级的问句。

## 2. 【设计理念 · 交互】需要改造的交互点

以下为表现层与流程改造，按玩家路径顺序列出。

### 2.1 封面

- 题名下方新增一行**题记**（全作之问），字号小于副标题、与副标题分行。无题记的作品不显示。

### 2.2 过场结束 → 「问句幕」

- 过场已有「题名幕」（卷名单独一屏）。对称地在**最后**加一屏「问句幕」：同一张插画、居中一行本卷之问、按钮仍为「进入本卷」。
- 问句幕是 UI 层的功能呈现，字来自数据里的本卷之问；过场正文末段的故事化问句与它可以是同一句，不算重复（一次在故事里、一次在题卡上）。

### 2.3 落地页签：从「故事」改为「时间轴」

- 首次进入本卷后落地**时间轴**而不是故事页（故事页只是把刚读完的过场再摆一遍）。
- 时间轴顶部（中列表格上方）常驻一行**本卷之问**。
- 空网格本身就是「谜题 + 收获」的预告：N 段未亮起的画面、几个剪影列头「？？？」。

### 2.4 时间轴空格：从「虚线框」改为「待亮起的画框」

- 未放卡的格子改成极淡暗色的 16:9 画框（与补完后 CG 铺满格子的视觉同构），让玩家一眼明白「每拼对一张，这里亮一幅画」。
- 玩法规则不变（可放置、可交换、放错零成本）。

### 2.5 关卡出口面板：题面开局可见、答案栏锁定

- 面板头部：「第 N 关 · 名称」下方那句 `intro` 换成**本卷之问**。
- 卷末题目**不再折叠到 70%**：标记为「开局可见」的题面从进入本卷起就展示，答案栏为灰色锁定态（虚线框 + 锁标）；标记为「开闸后可见」的题显示为「？？？」占位，70% 后展开。
- 每道题的答案栏在**其答案进入候选池时**（对应档案页补完 / 卡归位）点亮金边并轻闪一次，表示「这题现在能答了」；进度 ≥70% 前仍不可提交（点击 toast「进度到 70% 后可作答」）。
- 「展开问题」按钮语义改为「开始作答」（70% 可点）；进度条、里程碑圆点、100% 自动填写维持不变。

### 2.6 新手引导：从「页签巡礼」改为「问题 + 收获」，教学延后到用到时

- 删除开局的四步页签巡礼（故事 / 情节卡 / 档案 / 时间轴各是什么）。
- 「你的目标」弹窗重写：
  - 标题 = 本卷之问；
  - 正文 1 句：读残页，把问题里的人与事找回来；
  - 三行收获：「每补完一页，画卷亮起一格」「人物的档案会一页页解开」「答出卷末几问，进入下一卷」。
  - 不再写流程步骤（流程留给「玩法说明」）。
- 页签教学改为**触发式**：第一次拿到可归位的卡时教时间轴放置；第一次有词条熟悉度读满时教档案分析；第一次有可答题时教关卡出口。
- 现有的「点词条 → 词条卡 → 填空 → 搜寻 → 新卡 → 体力 → 推荐搜寻」链保留。

### 2.7 故事页

- 不再作为落地页；目录与内容不变。开场条目在过场读完后即解锁（现状）。

### 2.8 常驻提示（顶栏「提示」）

- 列表首条固定为本卷之问（不可点、只作提醒），其余条目照旧。

## 3. 【引擎改造】需要对引擎与数据做什么（通俗说明）

### 3.1 数据文件 `final_game.json` 新增三处

| 位置 | 新增内容 | 作用 |
| --- | --- | --- |
| `meta.tagline` | 一句话（可选） | 封面题记（全作之问） |
| `gates[].question` | 一句话（必填） | 本卷之问；过场问句幕、时间轴顶部、出口面板头部、目标弹窗、常驻提示首条共用这一句 |
| `gates[].blanks[].revealAt` | `"start"` 或 `"gate"`（缺省 `"gate"`，保证老作品行为不变） | 该题题面是开局可见还是开闸后可见 |

`gates[].intro` 保留不删，但界面不再显示（避免老数据报错）；后续作品可以不写。

### 3.2 校验器 `tools/validate_data.py` 新增检查

- `gates[].question` 必填、以「？」结尾、≤30 字、无第二人称、无玩法词汇（复用现有故事框词库）。
- `meta.tagline` 若有，同上规则。
- 每卷 `revealAt="start"` 的题 ≥3 道；这些题面中不得出现本卷任何待猜答案（人物 / 地点）的显示名。
- `levelIntro[N]` 最后一段必须含「？」（警告级，允许人工判定豁免）。
- 开局解锁卡（`startUnlocked`）每卷恰 2 张（警告级；老作品可豁免）。
- 回顾末页与结局的「回应问句」不做机械校验，列入人工复查。

### 3.3 前端改动（按文件说人话）

- **封面**：读 `meta.tagline`，有就多显示一行。
- **过场**：在最后加一屏「问句幕」，显示 `gates[当前卷].question`；按钮与键盘推进逻辑复用现有。
- **进入本卷后的落地页**：首次进入从「故事」改为「时间轴」。
- **时间轴**：表格上方新增一行本卷之问；空格样式改为暗色画框（只改样式，不改放置逻辑）。
- **关卡出口面板**：
  - 头部一句换成 `question`；
  - 题目列表始终渲染，按 `revealAt` 决定显示题面还是「？？？」；
  - 答案栏三态：锁定（灰）/ 可答（金边，答案已进候选池）/ 已锁定正确；
  - 70% 之前点击答案栏只提示，不弹候选；70% 后行为同现在。
- **新手引导**：删掉四步页签巡礼；「目标」弹窗改为读 `question` + 三行收获文案；新增三条触发式教学（首次可归位 / 首次可分析 / 首次可答题），文案进 9 个语言包。
- **常驻提示**：首条固定为 `question`。
- **DEBUG 文案编辑器**（`GateEditor` / `MetaEditor`）：加 `question`、`tagline`、每题 `revealAt` 的编辑框。
- **多语言**：`question`、`tagline` 属于可译字段，XDD 的 8 个平行语言包要同步补；新增的 UI 文案（教学三条、目标弹窗、锁定态 toast）进各语言包。

### 3.4 需要同步更新的测试与文档

- Playwright：落地页从 `notes` 改为 `timeline`；「展开问题」在 70% 前的断言改为「题面可见、答案栏锁定」；新手引导步骤顺序变化。
- 通关模拟（校验器里的 bot）：不受影响（它不看题面可见性）。
- `doc/02-data-schema.md`（新字段）、`doc/03-gameplay-logic.md`（闸门可见性、落地页、引导触发）、`doc/09-ui-conventions.md`（画框空格、问句幕）、`README_game.md`（第 1 部分规则并入 §4.5 / §4.7，红线速查同步）。

### 3.5 兼容性

- 老作品（围攻 / 坏血 / 谜案 / 围城 / ttdg）不写 `question` 时：校验器报设计规范错（wip 档拦、final 档只提示）；前端回退显示 `gate.intro`、题面全部按「开闸后可见」处理、落地页仍改为时间轴。老存档不受影响（新字段都在静态数据，不在存档里）。
