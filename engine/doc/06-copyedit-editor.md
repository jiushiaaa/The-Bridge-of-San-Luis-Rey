# 06 · DEBUG 内容编辑器（后端在线版专属）

> 上级索引：[README_dev.md](../README_dev.md)　·　相关：[02 数据 schema](02-data-schema.md)、[04 美术管线](04-art-pipeline.md)、[07 如何修改内容](07-content-authoring.md)、[12 回顾本关故事](12-story-recap.md)

**在游戏内改内容的工具，覆盖 `final_game.json` 的全部字段**：后端（6872）运行时（dev 5174 需与后端同时运行，/api 经 vite 代理过去），各界面底部出现 `DEBUG-…` 按钮（`.btn-debug` 同款虚线红），点开对应编辑器弹窗，改完点「保存并生效」→ 回写 `workspace/{作品}/final_game.json` 并**立即在当前对局生效**（无需刷新/重 build）。离线单文件版与后端未启动时按钮一律不出现（`copyeditAvailable`，启动时探测一次）。**非简体界面不出现编辑入口**（避免把语言包写回简体真源，见 [13](13-i18n.md)）。

## 1. 数据通道（`game/copyedit.ts` + `backend/server.js` 的 `/api/*`）

- 启动时 `GET /api/data?game=` 拉磁盘上最新 JSON **覆盖构建期内联数据**（1.5s 超时，失败回退内联）——后端版 dist 是旧构建也能读到最新文案；这是「数据内联、无运行时 fetch」前提的唯一受控例外（离线版不发请求，见 [11 跨模式踩坑](11-cross-mode-pitfalls.md)）。拉到的始终是简体真源，存进 `zhSource`；仅当前语言为 zh-CN 时才用来替换内存数据。
- 保存 = 编辑器把改动套在当前数据的深拷贝上 → `POST /api/data` 全量回写（服务器写前自动备份到 `workspace/{作品}/DEBUG/copyedit_backups/`，保留最近 20 份；缩进按原文件探测保持）→ 成功后 `replaceGameData` 内存热替换 + 触发全量重渲染。
- **存档消毒**（保存后自动，改数据不坏档）：blanks 变动的卡重置填空/补完/归位锁定；行列变动后越界放置退回待归位、rowHints 过滤；全词条熟悉度按新上限封顶（上限 `familiarMaxOf` 缓存清空自动重算）；档案字段结构/答案变动的留白重置作答、`pagesDone` 重推；闸门题数变动重置该闸门作答（passed/得分保留）。
- 换图 / 换音频 = `POST /api/upload`（限 `*-assets/` 内的 jpg/png/webp/mp3，旧文件同样先备份；mp3 上传后若正在播这一曲，`bgm.reloadBgmFile` 立即重载），**上传立即写盘生效**（无需点保存），`bumpAssetVersion` 给 assetUrl 加 `?v=` 强刷；词条原本无图时上传后自动把默认路径（`{前缀}-assets/avatars|images/{eid}.jpg`、CG 为 `cg/{cardId}.jpg`）写回字段。
- **AI 重绘** = `POST /api/regen-image`（body `{prompt, ratio, refs}`）→ 服务器备份旧图 → 跑 `tools/regen_image.py`（超时 15 分钟）。prompt 只写画面原文，画风后缀由 `tools/art_spec.py` 按用途自动拼，与批量生成完全同规则（见 [04](04-art-pipeline.md)）。情节卡 CG 重绘完成后编辑器会把新图取回来重测亮度、回填 `cgDark`。
- **重切 favicon** = `POST /api/favicon` → `tools/gen_scene_icons.py 作品 --favicon-only`。
- 保存成功后自动 `POST /api/validate`（服务器 spawn `python tools/validate_data.py 作品id`），结果显示在编辑器底部（通过 ✓ / 问题输出可展开 / python 缺失降级提示）。

## 2. 两档严重度（使用者与时机）

编辑器与校验器用同一套划分（README_game §9）：

- **完整性错误**（✕，恒禁用保存）：引用不存在的词条/卡、名字重复、时间轴坐标越界、发言 slot 不存在、段落全空……放过去数据就是坏的。
- **设计规范**（wip 期是 ✕，作品标 `meta.status = "final"` 后降级为 ⚠ 不阻断）：字数档、`tier` 分层规格、留白答案分布、时间轴密度、故事框措辞、回顾字数占比……
- `final` 时弹窗头部显示「内容总监模式 · 规范仅提示」徽标。档位在「作品设置」编辑器里切换。

## 3. 编辑器一览（`components/copyedit/`）

弹窗壳 `.ce-modal` 复用 `.overlay/.modal`；选词条/选卡一律用带头像名字的选择器（复用 SlotPicker，z 序在编辑器之上），作者全程不接触 id。

| 编辑器 | 入口 | 能改什么 |
| --- | --- | --- |
| **作品设置** `meta` | DEBUG 弹层 · 内容编辑 | 标题/副标题/**题记 `meta.tagline`（全作之问，问句、≤30 字、无第二人称/玩法词汇，可留空）**/版本；**完工状态 `meta.status`**；体力五参数；全卡平均字数 X；**六段全局画风** `meta.art`；标题图/结局图/主题图标（含 prompt 与 AI 重绘）；重切 favicon |
| **关卡管理** `levels` | DEBUG 弹层 · 内容编辑 | 每关的时间轴/卡数/档案页/闸门/过场/回顾**齐备性总览**；末尾**新建一关**（同时补时间轴+闸门+过场）、**删末关**；直达各分项编辑器；**新建情节卡** |
| **词条库** `entries` | 词条库面板底部 | **新建/删除词条**（删前扫全部引用点，有引用拦下并列位置）；分类 `type`、重要度 `tier`、名字、简介；**开局赠送词条** `levelStartEntries`；头像/词条图 + `avatarPrompt`/`imagePrompt`/`look` + AI 重绘 |
| **情节卡** `card` | 打开某卡时正文底部 | **顶部「本关全部情节卡」导航表**：本关卡片按时间轴 行×列 铺开（列头带人物头像、格内标题 + 形态/难度/开局），当前卡高亮，**点任一格即切到那张卡、下方编辑内容即时刷新**（有未保存改动先确认；不动返回栈）——玩家侧拿卡随机，作者侧按故事顺序逐卡过文案就靠它；卡的格位不再在本编辑器里改，「调整格位 →」跳时间轴编辑器的格子分配；**关卡 / 形态 / 难度 / 开局解锁**（改关卡后撞格自动与占位卡交换）；**字数档 `len`**（按正文实时判定并可一键采纳）；标题（提示语已随 `hints` 字段废弃，编辑器不再提供）；CG 换图 + `cgPrompt` + `cgChars` + AI 重绘（自动重测 `cgDark`）；人物空增删（删除自动重排 NPC 编号并三处同步）；地点空开关 + 多答案自动组数组；逐句正文（类型、气泡名三选、插入词条/NPC 标记、实时预览）；**删除这张卡** |
| **时间轴** `timeline` | 时间轴中列底部 | 时间行增删改序（卡的行下标自动重映射）；**情节列列名可改**（同步全卡 `col`）；人物列增删排序；格子分配总览表（点格换卡、占用自动交换）；**四条密度红线实时检查**（每行≥2、情节列每行恰1、人物列≥2、角色列总填充>40%）；新建情节卡 |
| **故事回顾** `recap` | 时间轴中列底部 / 回顾长廊底部 | 见 [12 回顾本关故事](12-story-recap.md)：按建议一键切页、行区间、覆盖卡、逐段旁白与引语气泡，**字数目标区间实时显示** |
| **闸门** `gate` | 关卡出口面板底部 | 关名只读展示（取过场首段卷名，要改去「过场」编辑器；`gates[].title` 字段已删除）、**本卷之问 `question`**（规范类：问句、≤30 字、无第二人称/玩法词汇）、旧开场语 `intro`（界面已不显示）、题目增删排序、答案二选一（词条/剧情卡标题）、**每题可见时机 `revealAt`**（开局可见 / 开闸后可见「？？？」；规范类：≥3 道开局可见，且开局可见的题面不得含本关任何空位答案的词条名）；**删除整扇闸门**（只允许末关，会少一关，需二次确认） |
| **档案** `archive` | 档案详情底部（弹窗内可切任意词条） | 页（属关、标题）与字段（标签 + 文本/留白切换）增删排序；留白候选池 `pool` 按答案分类自动推导；词条大图；**tier 规格与全作留白分布实时统计**（页数/字段数/每页留白数/单答案 ≤12% 且 ≤5 次/去重率 ≥60%） |
| **过场与结局** `frame` | 关卷过场 / 结局界面底部；关卡管理 | `frame.levelIntro[n]` 与 `frame.ending`（标题/段落/落款）逐段编辑；「故事框只讲故事」实时检查 |
| **背景音乐** `bgm` | DEBUG 弹层 · 内容编辑 | `assets.bgm` 全部曲目按封面 / 各关 / 结局分组：id、曲名、阶段、绑定卡（下拉，限本关卡；空 = 开篇曲）、文件路径、`tags`、`note`、Suno `prompt`；**试听 + 更换音频（mp3 上传即写盘）+ 复制prompt**；新增 / 删除曲目；顶部按 [14](14-bgm-pipeline.md) 公式实时自检（每关曲数、开篇曲恰 1、同 row 多曲）。**刻意不提供「重新生成」**——生成走 `tools/gen_bgm.py` |

**自动算出来、不用手填的东西**：字数档 `len` 建议值、`cgDark`、留白候选池 `pool`、熟悉度上限 旧→新、
时间轴四条密度、留白答案分布占比与去重率、回顾的建议页数与每页目标字数、NPC 编号重排、
撞格交换、favicon 裁切。

**结构性增删走 `game/content.ts`**（新建/删除卡、新建/删除关卡）：这些操作要同时动好几张表，
不适合放进单个编辑器的草稿里，一律**立即写回 JSON**，写完再打开对应编辑器细调。所以在时间轴编辑器里
点「新建情节卡」之前，请先保存本页尚未提交的行列改动。

## 4. dev 模式注意

`vite.config.ts` 对 `final_game.json` 关闭了 watch（否则每次保存触发整页刷新、毁掉编辑弹窗）；手工在编辑器外改该文件后需自己刷新页面（启动拉取会给到最新内容）。
